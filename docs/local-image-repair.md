# 图片局部编辑

入口：历史生成结果或素材库 → 图片预览 → 详情下方「局部编辑」。2026-10-22 更新为统一图片画布：进入局部编辑只切换中间信息栏，左侧原图、视图变换、常驻工具栏及右侧缩略图保持原位；最终视觉遵循 DESIGN.md。

## 当前能力

- 预览工作区按需加载 react-konva；原图使用同一图片节点，透明标注层复用相同视口和变换，标注不烧录进原图。拖动创建最多 8 个编号矩形，每个区域最多 900 字修改说明；选框与右侧卡片双向选择。
- 选框可移动、从四边或四角自由调整大小，不锁定比例，并限制在原图内；用户界面不显示左／上／宽／高输入，坐标仅在内部保存并编排进提交指令。鼠标反向框选也转换为正宽高。
- 详情与编辑共用 100%～500% 缩放、参考图查看器的滚轮灵敏度与缓动；抓手或按住空格拖动平移，适应画布重置为完整居中的视图。切换查看／编辑模式不重置缩放和平移。编号和控制点保持屏幕尺寸。工具与表单使用 HeroUI。
- 编辑草稿由 Zustand 按组织、用户及原图分隔，仅保存在当前页面会话；返回详情、在仍处于编辑模式时切换图片不会清空，刷新不保证恢复选区。退出预览时若还有未提交选区，先确认「退出局部编辑？」，确认后清空该图片的未提交区域；取消则保留。
- 一次提交一张新图片。保留原图和修复草稿，后台完成不会自动切换查看对象；点击「查看修改版」关闭详情及素材库弹层，跳转到工作台该次生成的历史记录，完整显示首行任务信息；历史列表尚未同步时按任务ID读取真实记录，不在弹层内另开修改版预览。

面板采用“修改图片”MVP：只展示区域编号、修改说明、「添加区域」和「立即生成」，积分以共享币图标嵌在按钮文字后；无重复原图、图片编号、坐标、输出参数、独立计费行或“原图保留”说明。未添加区域或任一说明为空时生成按钮保持禁用。区域说明由 `RepairRegionCard` 封装，画布、计费和提交边界保持原有能力。

## API 与任务

复用 `POST /api/v1/image-tasks`：`referenceAssetIds` 只包含当前原图，`count=1`；各区域原图像素坐标与说明编排进现有 `prompt`，由原有图片编辑 provider、PostgreSQL/outbox、独立 Worker 和钱包流程执行。服务端继续校验参考图组织归属，未添加新接口、数据库表或契约字段。

这是参考图加坐标指令的编辑，尚无严格蒙版接口。界面说明尽量保留区域外内容，不承诺框外像素不变。输出自动采用原图最接近的受支持比例和分辨率档位，界面不重复展示这些参数；任意上传尺寸不保证原像素尺寸。

提交保留现有幂等键及完整请求，额外记录前端提交来源（不发送给 API）。网络结果不明时锁住选区和提示词，仅确认同一请求，不重新收费提交；其他入口不能误重放该修复请求。原请求入口未确认时也不能开始新的修复。任务按 ID 查询并展示真实状态，失败不自动重试。

## 验证

- `local-repair-state.test.ts`：原图边界约束、坐标与提示词配对、受支持输出规格。
- `tests/e2e/local-repair.spec.ts`：多区域、真实鼠标框选与控制点缩放、画布缩放不改原图坐标、关闭恢复草稿、单张提交、丢响应同键确认、保留原图与窄屏。
- `tests/e2e/preview-workspace.spec.ts`：同一图片／选区层跨模式不重建、视图变换保持、跨图草稿、撤销重做、工具键盘语义与适应画布。
- `tests/e2e/image-preview.spec.ts`：原有预览缩放、拖动、焦点与布局回归。

浏览器测试使用拦截接口，不调用付费模型。真实模型对多区域指令的执行质量需要使用有额度的账号另行验收。
