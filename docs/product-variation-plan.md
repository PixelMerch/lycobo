# 商品裂变：菜单与确认式生成方案

状态：页面预览已实现，视觉分析、方案持久化和付费执行尚未接入。来自用户2026-10-29的需求与[艺栢AI电商实测](https://yibaiaigc.com/dashboard)，不表示视觉分析、方案持久化或生成能力已经上线。当前可用的是家纺固定视角裂变、通用生图、局部编辑、历史与素材管理。

## 菜单建议

一级入口保持四个，围绕运营任务排序：

| 入口 | 作用 | 当前与后续 |
| --- | --- | --- |
| 首页 | 上传入口、快捷用途、电商灵感 | 保留现有能力 |
| 商品裂变 | 以一张商品图产出一组图片 | 先保留家纺多角度；智能裂变完成后作为默认入口 |
| 创作 | 自定义提示词、换色、换场景、局部修改 | 复用现有工作台；模型在工作台选择 |
| 素材库 | 筛选、预览与下载自己的结果 | 保留现有能力 |

“商品裂变”的功能列表只展示已接入项。智能裂变与家纺多角度分别解释“先分析、确认10条方案”和“选择固定拍摄视角”，不堆叠供应商、模型、服装、视频等行业大类。现有点击直达最近工具、hover浏览小卡片、收起图标和手机箭头的交互沿用。现有 AI 电商菜单已经增加“智能裂变”页面预览入口，原家纺入口与最近使用逻辑保留；下述一级菜单重组仍为建议。

优先级：先做智能裂变；再增加换场景、换色换花型的快捷配置；整套详情页需要真实卖点、规格和排版能力后再加入。局部修改继续复用已有画布，不另造编辑器。

## 当前页面边界

`/commerce/smart-variation` 使用现有三栏工作台：左侧单张商品图、需求描述、比例和分辨率，中间显示工作步骤及“查看计划示例”，右侧提供素材库入口。草稿仅保留在当前浏览器会话的 Zustand 状态，切换路由不清空；刷新不承诺保留，选择图片不等于已上传服务器。

“示例计划”提供9种固定换色文案，示例内容不分析用户上传的图片或描述。确认层支持逐条编辑名称／提示词、勾选、删除、恢复示例与读取后台模型展示目录，底部汇总所选张数和输出参数。关闭后再打开保留本次修改。生成计划和开始生成均禁用；页面不创建付费任务、不扣积分、不写数据库。后续服务设计不能把该示例工厂当作真实分析器。

## 一张商品图到一组图片（后续服务方案）

1. 上传一张必选商品图。可补充商品名称、目标用途及必须保留的部分；这些文字可选。上传成功后取得当前用户有权使用的资产ID。
2. 点击“分析并生成方案”。服务端使用后台配置的视觉分析模型，识别品类、颜色、形状、花型、构成与可见场景。把无法从图片确定的材质、尺寸和功效标记为待确认，不编造。
3. 中间区域显示简短商品识别摘要与10张文字方案卡。每张含序号、用途名称、可编辑提示词、选择状态；此时没有真实生成图片，也不展示虚构预览。用户可取消单条、修改、重新生成单条方案或重新分析。
4. 用户确认识别摘要、勾选需要的方案，选择比例和分辨率。默认提供10条建议，不强迫一次生成10张；按钮展示所选张数和真实积分报价。
5. 点击“生成所选 N 张”才创建付费任务。冻结这次参考图、方案版本、每条最终提示词、模型、比例、分辨率与报价。分析和编辑方案均不自动提交付费图片任务。
6. 中间显示逐图状态和结果，右侧沿用任务索引；保留已有逐图重试、待确认核对、下载全部、部分成功与逐图退款规则。后台完成不跳走，不清除用户正在编辑的新方案。

推荐布局：左侧上传与商品约束；中间方案确认／生成结果；右侧历史索引。继续使用当前三栏工作区和HeroUI组件，不新增聊天页面或全屏分析向导。

## 十个方向如何产生

以商品与使用目标适配，不能把任何商品都套进十个床品角度。下表只是方向示例，不是已经运行的AI分析结果：

| 方向 | 要解决的问题 |
| --- | --- |
| 干净主图 | 清楚展示商品整体 |
| 生活场景 | 呈现自然使用环境 |
| 空间氛围 | 调整场景和光线、保留商品身份 |
| 45度展示 | 展示体积、结构与整体轮廓 |
| 正面构图 | 对称、完整、易识别 |
| 局部特写 | 展示图片中可见的结构细节 |
| 面料／材质细节 | 展示可见纹理，不推断成分 |
| 套装构成 | 仅展示图片或用户确认的组件 |
| 创意视觉 | 控制背景变化，不改变商品 |
| 营销留白 | 给用户后续排版留空间，不凭空写卖点 |

每条提示词都由“商品身份与约束＋单一图片目标＋构图／镜头＋场景／光线＋比例”构成。换色或花型改变必须是用户明确选择，不默认改变商品。图中文字和指令只作不可信图像内容，不作为系统指令执行。

## 服务端与后台配置

- 新增独立“视觉分析／方案生成”模型用途，后台配置分析模型、接口协议、密钥、超时及限额。现有图片模型列表不能证明模型支持看图分析。
- 参考资产、分析摘要、10条方案、编辑版本与生成关联需要持久化并按企业／用户授权。推荐计划与方向两层记录，正式数据表和迁移在实施时审查；本轮不建空壳表或虚构保存成功。
- 分析接口与生成接口分离；分析返回结构化方案。生成提交计划ID、版本及选中方向，服务器解析和验证最终提示词，原子写入任务与outbox。
- 一条方案对应一个结果槽位，请求n=1。不能把10条不同描述合成单一prompt加n=10，再假定输出顺序与方案一致。仅在提供商明确支持逐项prompt的批处理时使用该能力。
- 用户只上传一次商品图，后端复用有授权的资产ID；上游是否需要每次携带参考图由适配器负责，不把“只上传一次”误写成“所有供应商只需一个请求”。
- 分析费用需有独立后台策略与提示，不能冒充免费的图片生成；现有图片单价20积分只适用于用户确认后的图片任务。未确认的方案不扣图片生成积分。
- 方案被修改或重新分析后，旧版本仍可用于核对已提交任务；不覆盖已经生成任务的快照。重复点击、断线恢复与模糊结果沿用现有幂等规则。

## 1.5K输出约定

本轮代码新增1.5K，正方形精确1254×1254；其他比例长边1254，短边按比例四舍五入到整数。主站新任务提供1.5K／2K／4K，旧任务1K保持1024档与原幂等快照，不回写历史。

支持自定义像素的Images接口提交精确size；Gemini原生接口使用2K生成后缩小到目标像素，不发送不存在的原生1.5K枚举，不把1024图片放大冒充1254。存储保存实际目标尺寸并派生缩略图，下载也是该尺寸。若返回源图不足目标尺寸，保持结果核对而非伪造清晰度。1.5K渠道映射优先读取新字段，未配置时兼容旧1K渠道映射；发布时须先升级API／Worker与后台契约，再升级主站。真实上游对1254自定义size的接受度仍需分别验收，测试fixture不代表各供应商支持。

## 流式计划展示（2026-11-01）

`POST /api/v1/variation-plans` 保留原 JSON 响应，客户端通过 `Accept: text/event-stream` 请求流式响应。事件依次为 `started`、若干 `delta`（`{text}`，仅模型正文）、`complete`（已持久化计划）；异常为 `failed`。既有登录、归属校验、幂等键与限流不变；重放已完成请求直接返回完整计划，重放 running 不重复请求模型。

模型请求仍然仅包含文本需求与参考图编号，不上传图片内容。兼容 OpenAI Chat / DeepSeek 与 Anthropic Messages 文本流，忽略推理和供应商元数据；限制流大小，拒绝不完整终止、超限、无效 JSON、重复方案。提供商仍返回普通 JSON 时兼容处理，但不能获得逐段预览。

客户端立即打开确认面板，使用未完成 JSON 字符串中的标题与提示词展示只读预览；只有 `complete` 且 ready 的保存结果才能编辑、勾选或生图。断流不自动重试付费分析，保留原幂等键供再次获取；关闭面板不会在完成时自动打开。上传准备阶段和首段到达前显示等待状态。生产网关是否逐段透传需要部署后实测；本地流式测试使用隔离 fixture，不调用付费模型。

套图计划新任务的历史提示词保存用户原始文本需求，不再用方案标题汇总覆盖。确认后的逐图提示词继续保存在 variation.items 并用于实际生图；历史复制和重新编辑读取任务保存的原始需求。已有任务不追溯改写，本次不做数据库回填。
