# 套图计划

本文记录 `/commerce/smart-variation` 的计划生成、确认与执行约束。导航和功能范围见 [PRD](../PRD.md)，布局与交互以 [DESIGN](../DESIGN.md) 为准。

## 当前流程

1. 用户填写文本需求，可上传参考图并在文本中引用图片编号。规划阶段优化文本，不将参考图内容发送给规划模型；网页链接通过 DeepSeek 官方 Fetch 读取。
2. 点击生成计划立即打开确认面板，流式展示返回的标题和提示词。计划按企业、用户和幂等键持久化，不扣生图积分，不自动创建图片。计划保存完成后，用户可编辑、选择和删除方案。
3. 确认生图时才提交图片任务，服务端校验计划与参考资产归属，保存原始需求和逐图方案快照，沿用任务、outbox 与钱包扣退费机制。每条方案独立生成一张图片。
4. 历史记录展示用户原始需求；实际图片生成使用确认后的逐图提示词。后台完成不切换当前工具，不覆盖正在编辑的草稿。

规划与生图是两个阶段，不用示例计划冒充模型结果。失败、断流和不确定状态不得自动重复提交付费请求。模型配置见 [模型服务](model-services.md)，图片执行与核对见 [任务生命周期](task-lifecycle.md)，计费见 [共享钱包](enterprise-wallet.md)。

## 1.5K输出约定

1.5K档位的正方形精确1254×1254；其他比例长边1254，短边按比例四舍五入到整数。主站新任务提供1.5K／2K／4K，旧任务1K保持1024档与原幂等快照，不回写历史。

支持自定义像素的Images接口提交精确size；Gemini原生接口使用2K生成后缩小到目标像素，不发送不存在的原生1.5K枚举，不把1024图片放大冒充1254。存储保存实际目标尺寸并派生缩略图，下载也是该尺寸。若返回尺寸在每个方向与目标相差不超过15像素，接受中转站对齐结果，保留实际像素、不补边、不放大；明显不足目标尺寸仍保持结果核对。1.5K渠道映射优先读取新字段，未配置时兼容旧1K渠道映射；发布时须先升级API／Worker与后台契约，再升级主站。真实上游对1254自定义size的接受度仍需分别验收，测试fixture不代表各供应商支持。

## 流式计划展示（2026-11-01）

`POST /api/v1/variation-plans` 保留原 JSON 响应，客户端通过 `Accept: text/event-stream` 请求流式响应。事件依次为 `started`、若干 `delta`（`{text}`，仅模型正文）、`complete`（已持久化计划）；异常为 `failed`。既有登录、归属校验、幂等键与限流不变；重放已完成请求直接返回完整计划，重放 running 不重复请求模型。

模型请求仍然仅包含文本需求与参考图编号，不上传图片内容。兼容 OpenAI Chat / DeepSeek 与 Anthropic Messages 文本流，忽略推理和供应商元数据；限制流大小，拒绝不完整终止、超限、无效 JSON、重复方案。提供商仍返回普通 JSON 时兼容处理，但不能获得逐段预览。

客户端立即打开确认面板，使用未完成 JSON 字符串中的标题与提示词展示只读预览；只有 `complete` 且 ready 的保存结果才能编辑、勾选或生图。断流不自动重试付费分析，保留原幂等键供再次获取；关闭面板不会在完成时自动打开。上传准备阶段和首段到达前显示等待状态。生产网关是否逐段透传需要部署后实测；本地流式测试使用隔离 fixture，不调用付费模型。

套图计划新任务的历史提示词保存用户原始文本需求，不再用方案标题汇总覆盖。确认后的逐图提示词继续保存在 variation.items 并用于实际生图；历史复制和重新编辑读取任务保存的原始需求。已有任务不追溯改写，本次不做数据库回填。

## DeepSeek 网页链接分析

套图计划识别创作需求中的 HTTP/HTTPS 链接（最多 3 个，去重并去掉 fragment），通过 DeepSeek 官方 `POST https://api.deepseek.com/v1/tools/fetch` 获取标题和 Markdown，再将网页资料与原始需求交给规划模型。没有链接时不调用 Fetch。当前仅支持规划渠道为官方 `https://api.deepseek.com` 的配置，复用该渠道服务端密钥；不把第三方渠道密钥发送给 DeepSeek，不自行抓取目标网页，也不发起全网 Search。

SSE 增加可选 `status` 事件：`reading`、`planning`、`link_failed`；旧客户端可忽略。前端显示真实读取阶段；读取失败停止模型调用并保存失败状态，清理本次待处理请求键，保留草稿，提示用户粘贴商品信息后重试。不回退到猜测商品信息。重放已经完成的计划不会再次调用 Fetch。中断后重放的失败计划使用现有通用失败提示。

Fetch 总等待上限 15 秒、JSON 响应最多 1 MiB；每页最多向模型提供 10,000 字符正文与 300 字符标题。只缓存成功读取结果，按组织和用户隔离，5 分钟有效、每个 API 服务实例最多 100 条；实例重启或扩容可能重新读取，不保证跨实例缓存命中，不增加数据库访问。不自动重试 Fetch，不记录网页内容、完整 URL 或供应商响应。所有请求只发到固定官方端点，禁止跳转转发密钥；用户链接不能带账号密码、非标准端口或 IP 地址。网页内容按不可信资料处理，不能改变用户要求或输出格式，不作为指令执行。

DeepSeek Fetch 与规划文本 token 分别计费，价格以官方文档为准。登录、验证码、站点访问策略、空内容、额度或鉴权错误均可能导致读取失败；不保证识别所有返回 HTTP 200 的拦截页。仅分析文字，不读取或导入商品图片；实际生图仍需用户上传参考图。文档依据：[网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)、[Fetch API](https://api-docs.deepseek.com/zh-cn/api/fetch/)。

上传参考图在服务端验证后等比例缩小至宽、高均不超过3840像素，较小图片不放大，以压缩PNG入库。此上限独立于生成请求尺寸；向中转站发送参考图时，不透明图片可转JPEG压缩，透明图片保持PNG。
