# 图片 Webhook 与低频批量同步

图片完成回调已上线，`IMAGE_WEBHOOK_ENABLED=true`。协议来源：[FluxPort 图片 Webhook 文档](https://uselg.top/docs#api-image-webhook)。

## 链路

1. API 原子保存任务及 outbox，独立消费者向中转站提交一次生图。
2. 新任务快照启用 webhook 时，消费者保存中转任务 ID、经过验证的查询路径，释放执行租约并退出，不占住云函数等待生成。
3. 中转站 POST `/api/v1/webhooks/fluxport/images`。API 对原始字节验证 HMAC-SHA256、时间戳（±300 秒）及事件头，只持久化事件 ID、来源、任务 ID、类型、状态；不保存或信任回调里的图片地址、提示词。
4. 回调与任务关联后，在同一数据库事务里推进 outbox，再唤醒消费者。图片任务唤醒只处理图片队列。消费者使用已有查询路径 GET 原任务，验证结果、写入现有私有云存储，最后完成任务和结算。回调本身不直接扣费、退款，也不提交新的付费生图。
5. 前端仅在有未完成任务且页面可见时查询：十分钟内每 15 秒，之后每 30 秒；失败退避最高 60 秒。每请求最多 50 个任务，更多任务按批串行查询。完成后停止，批次失败时保留原任务。批量接口仍验证当前用户的组织成员身份并限定组织归属。

## 竞态和兜底

- 事件 ID 按生图 Key 的 SHA-256 来源指纹去重；同 ID 内容冲突拒绝。任务关联按来源和中转任务 ID 唯一。
- 回调早于提交响应入库：先持久化，登记任务时原子消费并使原任务立即可查。这次调用写完当前批次的回执后退出，另一次异步调用查原任务。
- 回调在消费者持租约期间到达：保留未消费事件；本次查询仍 pending 时登记等待会消费事件，不丢失唤醒。
- 已完成、明确失败或被重试替换的旧任务，迟到回调不能重新结算。未知结果不自动退款；迟到通知可重新核查原任务。
- 默认等 60 秒没有完成回调，任务允许补查。可见页面下一次批量状态查询会补唤醒；每批最多一次唤醒，同任务单 API 实例内至少间隔 15 秒。
- 页面关闭时保留现有每 3 小时消费者定时兜底。因此回调丢失且无人打开页面时，最迟可能等到下一次定时运行才补查；本轮没有提高定时器频率。
- 新 webhook 任务采用 600 秒正常核查预算；超过预算仍对原任务最后 GET 一次，有结果则保存，没有确定结果则标记待核对，不重发付费请求。旧任务快照不改，继续原有执行策略。
- 事件记录保留 7 天，维护任务每次最多清理 1000 条；任务关联保留用于迟到回调判断。去重记录过期后，终态和旧尝试检查仍防止重复结算。

## 发布顺序与后续更新

1. 审查共享契约和迁移；先应用 CloudBase 迁移 `20261101040000_provider_webhooks.sql`，再部署新 API、消费者和前端。Node PG 的对应迁移为 `0037_provider_webhooks.sql`，两种生产数据库只运行各自迁移通道。
2. 服务端保持 `IMAGE_WEBHOOK_ENABLED=false`，先在 API 配置 `IMAGE_WEBHOOK_SECRET`（随机 16–256 字符）。API 通过现有 `STANDALONE_IMAGE_API_KEY` 识别该回调所属来源；密钥不得进入前端或 VITE 环境变量。
3. 在中转站**当前生图 Key**上启用图片完成回调，填写现有公开 HTTPS API 入口的 `/api/v1/webhooks/fluxport/images` 和相同签名密钥。无需更换用户访问域名。中转站按 Key 配置，不是每次生成提交 callback URL；账号管理接口与生图接口使用不同凭据。
4. 验证回调能到达接收端后，API 设置 `IMAGE_WEBHOOK_ENABLED=true`，此后创建的新任务快照启用等待；已有任务不被切换。检查 API 与消费者部署版本一致。
5. 用获准的实际任务验证“提交 → 回调 → GET 核查 → 云存储 → 前端完成”。本地测试仅使用模拟中转响应，没有验证公网回调、真实生图或真实存储写入。

生图 Key 更换会改变来源指纹，正在运行的旧任务可能无法由新 Key 回调关联，需先排空任务或等待兜底；签名密钥轮换也应协调中转站与 API。回滚时先停止新任务启用 webhook，保留接收端和已登记任务的补查能力。

## 资源与权限

减少的是逐任务 HTTP/RPC 调用、正常生图期间反复查中转站和云函数空等。批量接口仍读取 PostgreSQL；等待中的页面每 15 秒访问数据库可能继续保持共享 PG 活跃，因此不承诺 CU 按请求数量同比降低。

回调表开启 RLS 且不向浏览器角色提供策略；匿名、authenticated、service_role 都没有表的直接业务访问权限，仅服务端 service_role 可执行受限 SECURITY DEFINER RPC。批量 RPC 校验组织成员身份；回调 RPC 只能由已校验签名的服务端调用。函数固定 search_path，回调不回显请求头、环境变量或签名。数据库事务不包含网络调用。
