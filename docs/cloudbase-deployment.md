## GitHub 自动发布

`.github/workflows/deploy-cloudbase.yml` 替代已删除的 Cloudflare 发布工作流：main 的 push CI 成功 → 检出该 SHA → 确认仍为最新 main → 冻结安装依赖 → 构建前端（同一提交已在 CI 通过 `pnpm check`，发布时不再重复）→ 准备前后端包 → 更新已配置的三个云函数代码 → 验证 API → 发布共享静态托管。dev 和 PR 不发布；手动触发也只允许 main，且必须有该 SHA 对应的成功 push CI。

发布前再次检查 main，避免构建期间已有新提交却发布旧版本。同一环境的发布串行执行，不自动运行完整浏览器 E2E，不迁移数据库或上传业务运行密钥。

Actions 中完成构建，临时发布目录只复制 `apps/web/dist`。准备脚本拒绝环境文件、备份、服务器函数和符号链接；不上传仓库根目录、`.env` 或图片数据。Node/pnpm 沿用仓库固定版本，CLI 固定为 `@cloudbase/cli@3.8.11`，已通过实际 help 核对参数。

使用 `tcb hosting deploy --safe --verify` 将独立 Vite 产物发布到共享静态托管，忽略准备目录中的应用配置文件、不使用 prune。网关默认 HTTP 域名统一挂载前端、`/api` 和 `/_images`，保证 Cookie 同源。当前静态托管已启用，首页和错误页均已配置并回查为 `index.html`，支持 SPA 深链刷新。默认域名为平台测试入口，自定义域名另行核对备案、证书和套餐能力。

访问入口为 `https://lycobo-d9gyvxkegc54a1257-1311968085.ap-shanghai.app.tcloudbase.com/`。`tcloudbaseapp.com` 只承载静态文件，不含业务 API；发布包在应用启动前将该项目的静态域名页面转到网关，并保留路径、查询和片段。网关、自定义域名和本地开发不跳转，Cookie 继续使用同源策略。

## 部署凭据

GitHub 已创建 `cloudbase-production` Environment，仅允许 main 部署。凭据持有人须在该 Environment Secrets 中配置：

| 名称 | 内容 |
| --- | --- |
| `TCB_SECRET_ID` | 本项目部署身份的腾讯云 SecretId |
| `TCB_SECRET_KEY` | 对应 SecretKey |

权限限定到本项目发布所需能力，不使用主账号无限制密钥。数据库密码、企业 JWT 主密钥和图片供应商 Key 不进入前端部署环境。临时 device 登录授权不能复制到 GitHub 长期使用。

Environment 变量 `CLOUDBASE_RUNTIME_READY` 已设置为 `true`。后续 CI 使用固定版本 CloudBase MCP 的两段式代码上传，仅更新代码并保留云端运行凭据和配置；不会自动创建不完整后端或应用数据库迁移。

Secrets 仅在发布登录与后端代码传输步骤注入，不传入前端构建；任务结束后执行 CLI logout。本地提交不会自动推送或触发发布。

`TCB_SECRET_ID` 应为腾讯云 AKID 开头的 SecretId；工作流会提前拒绝将服务端存储 API Key 误填为发布身份的情况。控制台中的 `lycobo-private-storage` 资源 API Key 不用于这两个发布 Secret。

## 运行服务

- `lycobo-api`：HTTP 云函数，Hono，企业鉴权、业务 API、事件流；监听 0.0.0.0:9000。
- `lycobo-assets`：HTTP 云函数，签名绑定对象/用途/过期时间；校验 Origin/Referer 后读取私有云存储。默认不使用进程缓存，沿用既有授权测试。
- `lycobo-consumer`：独立 Event 云函数，完整等待任务处理；PostgreSQL outbox/claim 为持久来源，每次最多租用 20 条，同时 2 条提交或读取结果（生成期间以延后读取重叠），图片解码、编码与保存最多 2 条并行。不在 HTTP API 中执行后台付费请求。消费者已实际调用并返回 enabled=false、processed=0；正式切换前不启用定时触发器。

三个函数内存 512 MiB、Nodejs20.19，超时 API／消费者 900 秒、资源服务 60 秒。网关路由：`/` 到静态托管，`/api` 完整路径透传到 API，`/_images` 剥前缀到资源服务。

`scripts/cloudbase/prepare-runtime.mjs` 在仓库外空目录构建 Nodejs20.19 包，外部依赖固定版本，为 Sharp 下载 Linux x64/glibc 二进制；包只含编译代码、依赖和启动文件，不含 .env、用户图片、数据库备份或源目录。两个 HTTP 包含可执行 scf_bootstrap，Event 包使用 index.main。

浏览器只请求业务 API，不直接使用服务端 CloudBase API Key。保留原企业账号、密码哈希、JWT、Cookie/CSRF 和组织成员关系。Node API 拒绝同时配置 CloudBase 与 DATABASE_URL，防止两个库混用。

图片运行仓储通过固定操作分支承接主站任务提交、钱包查询/扣费/退款、幂等重试、归属校验、素材、裂变计划、outbox 租约、任务认领、供应商轮询、完成、超时保留及人工核对。SQL 不接收任意语句或标识符。执行与账务保持原子性，外部供应商调用仍在事务之外。

运行角色不能创建 public 对象，不能直接读写 public 业务表或序列；只授予固定业务函数执行，内部辅助函数不向 service_role 开放。

CloudBase 默认不开启 SSE（`IMAGE_EVENTS_ENABLED=true` 才开启）：每条连接按时长计费且每 3 秒查询数据库，打开的页面会让 API 与共享 PG 持续计量。浏览器只轮询未完成任务，计费分析见下文“运行计费优化”。

首次创建函数使用 `node --env-file=.env scripts/cloudbase/bootstrap-runtime.mjs <准备好的运行目录>`。该入口通过官方 CLI 配置文件直接引用本机凭据；临时配置在函数包外、权限 0600，并在结束时删除。它不打开网关、不启用生图或定时器。

## 主站私有图片

主站使用 CloudBase PG 原生存储 `lycobo-images` 私有桶，不使用旧 NoSQL COS 接口。[追加迁移](../cloudbase/migrations/20261031223300_private_image_storage.sql) 限定单对象 32 MiB、PNG/WebP。原图、兼容 PNG 缩略图、WebP 预览及缩略图保留原对象 key 约定。新生成和上传的图片只写入原图与两个 WebP 变体；兼容 PNG 缩略图（实测平均 497 KiB，是 WebP 缩略图的 16 倍）只有套图计划规划会读取，首次读取时从原图生成并保存。

服务端配置如下，禁止使用 VITE_ 前缀：

```dotenv
CLOUDBASE_ENV_ID=lycobo-d9gyvxkegc54a1257
CLOUDBASE_STORAGE_BUCKET=lycobo-images
CLOUDBASE_APIKEY=<server-api-key>
```

`CLOUDBASE_APIKEY` 是资源数据面服务端凭据，不是 GitHub 发布密钥或浏览器 Publishable Key。此次经管理接口签发 `lycobo-private-storage` 运行凭据，只保存在被忽略、权限 600 的本地 `.env`；发布后端时仍须注入服务 Secrets。管理员在 CloudBase API Key 管理中撤销/轮换，并同步更新运行服务。凭据不进入文档或前端。

桶和对象表保留默认 RLS 拒绝，不开放 anon/authenticated 直接读写；后端 service_role 访问前由业务 API 验证企业身份和素材归属。资源访问保留绑定对象、用途和到期时间的签名，不改成永久公开链接。

`cloudbase-object-bucket.ts` 实现已实测的 PG HEAD/GET/PUT/DELETE，固定目标网关、30 秒超时、不跟随重定向、错误脱敏。一旦配置 CloudBase，404、鉴权错误、超时或服务故障均不会回退旧 R2/S3，避免已删除素材重新出现。

Node API 的 `object-image-store.ts` 使用 Sharp 完成解码校验、去元数据、PNG 原图和展示变体生成，无需 Cloudflare Images。付费原图先落盘到私有云存储，变体失败保留原图。CloudBase 三功能已开启并真实验收，正式域名尚未切换。

## 发布实现与注意事项

后端通过 `scripts/cloudbase/deploy-runtime.mjs` 发布：固定 @cloudbase/cloudbase-mcp 2.36.2、MCP SDK 1.32.2、COS SDK 3.0.0，依赖仅安装到 runner 临时目录，不进入应用包或根锁文件。MCP 获取环境自有 COS 桶的上传能力，限制区域、桶、代码前缀和函数名；三个代码包的全部分块同时传输（runner 到上海 COS 的单连接约 10 KB/s，总速率随连接数增长），COS SDK 按 1 MiB 分块、每包最多 16 路并发，单请求 90 秒空闲超时、最多三次刷新目标重试，仅输出百分比和脱敏错误码。MCP 工具调用逐个发出，仅 COS 传输并发。全部代码包传输成功后，才按 consumer → assets → api 顺序通过 MCP 逐个提交代码更新；任一传输失败则不切换任何函数，并删除已传对象。函数恢复 Active 且修改时间变化后，用 COS SDK 删除本次代码对象；某个函数切换失败时保留其已提交对象，只删除尚未提交的对象。管理凭据仅存在于进程内，不输出或写入应用配置。

MCP 安装在登录前的独立步骤完成（5 分钟上限），发布进程直接启动已安装的入口，避免发布时隐式下载。后端传输步骤上限 20 分钟，整体任务仍为 30 分钟；日志仅记录动作、传输进度和脱敏错误，不包含参数、响应、凭据或上传地址。

函数代码的 `CodeSha256` 与平台存储的 zip 一致，但平台会改写 HTTP 函数 `scf_bootstrap` 条目的权限和时间，存储包与上传包不同，因此不能据此跳过未变更函数。

静态托管使用 `tcb hosting deploy .` 的默认根路径。CLI 3.8.11 显式传 `/` 会在一致性校验中保留前导斜杠，误报全部 missing 并回滚；省略该参数后本地 94 文件发布成功，verified=true、failedCount=0。保留 --safe --verify，不通过关闭校验绕过问题。执行目录必须是独立发布目录，不能用 --cwd 代替进程工作目录后仍传 `.`。

GitHub 使用长期 SecretId/SecretKey，不能调用仅支持临时登录态的 MCP `get_temp_credentials`。COS 传输与清理在 CI 直接读取已配置的两个 Environment Secrets；本地 device 授权才走显式临时凭据接口。凭据仅在内存使用，两条路径均由回归覆盖，缺少配对字段时拒绝回退到其他身份。

官方参考：[CLI 函数代码更新](https://docs.cloudbase.net/cli-v1/functions/code-update)、[CI/CD 集成](https://docs.cloudbase.net/hosting/cli-devops)、[PG 云存储](https://docs.cloudbase.net/api-reference/webv3/storage)。

## 运行计费优化

2026-11-01 按控制台账单与监控核对个人版（每月 40,000 资源点）的计量方式：共享 PostgreSQL 以 5 分钟为计量单位，任一时段有访问即按 0.5 核计 150 核秒，本环境实测约 14 点/时段（197 点对应 2,073 核秒）；云函数按内存 × 时长计费，实测约 0.13 点/GBs（67.49 点对应 513 GBs）；数据库网关调用另按次计量。

优化前实测的主要消耗：

- API 的 SSE 长连接：每个打开的页面持续占用一个 512 MB 函数实例（10 分钟后重连），并每 3 秒查询数据库。2026-11-01 00:00–01:00 API 函数累计执行约 7,500 秒（约 3,750 GBs），普通请求只占很小部分。
- 消费者每分钟定时触发：每次 4 次数据库调用，使共享 PG 全天每个 5 分钟时段都计量，约 4,100 点/天，按月会超过套餐额度。
- 生成中历史列表每 5 秒刷新全部已加载分页，每页 3 次数据库调用。
- 生成排队等待由定时器决定：已有 92 张图的开始等待中位 16 秒、P90 50 秒，运行中位 74 秒、P90 120 秒。
- 2026-11-01 套餐周期截至 14:00 计 3,093 点（单用户），按 CLS 汇总与云监控 OutFlow 核对：约 1,200 点来自 PR #40 前打开的页面整夜重连已关闭的 SSE（01:49–08:59 每个 5 分钟时段都访问数据库）；约 460 点来自 10-31 夜间部署测试（SSE 长连接与每分钟定时器）。函数外网出流量 525 MB 中消费者占 459 MB：每生成一张图都把任务全部参考图以原尺寸 PNG（base64）重新发给服务商，5 张参考图的 5 张图任务约 100 MB；素材函数只有 3.6 MB，图片展示不是流量来源。

代码调整：

- CloudBase 默认关闭 SSE，前端只轮询未完成任务的详情（见[生图 API](image-generation-api.md#历史记录刷新策略)），空闲页面不访问 API 或数据库。
- 没有输出和参考图的任务不再查询图片位置，生成中每次轮询只需鉴权与任务两次数据库调用。
- API 提交或重试成功后同步唤醒消费者；消费者只用运行角色向 SCF 排队一次异步 drain，同步调用不访问数据库、不执行付费请求。drain 结束时仍有延后读取或剩余意向会自行续排，生成不再等待下一次定时器。
- 由唤醒触发的 drain 跳过事件保留清理和过期参考图清理，这两项留给定时或手动运行。
- 原图保存为启用自适应行过滤的无损 PNG：照片类样图小 11–25%，每百万像素约多 10–20 ms 编码；像素与格式不变。
- 消费者每次 drain 最多 2 个图片项在途（滚动补位）。异步服务商的图片项只在提交或读取结果时占用名额（约 10 s），生成期间以延后读取与其他图片项重叠。PR #41 曾改为 4 个在途，线上同类 5 张任务只提前约 12 s，峰值内存却从 278 MB 升到 381 MB（1.5K），4K 批次可能超出 512 MB；drain 被中止时不会续排，API 的补唤醒又只覆盖排队任务，生成中的图片项会等到下一次唤醒或 3 小时兜底，因此恢复为 2 个。图片解码、编码与保存最多 2 个并行，失败后不再开始新的付费请求。
- 发给图片服务商的参考图在发送前重新编码：不透明图片转为 JPEG（质量 92、4:4:4 色度），长边不超过 3840 px，家纺样图小约 5 倍、PSNR 40.8–49.9 dB；透明图片保持 PNG；未超尺寸且压缩结果不更小时使用原文件，无法解码时也保留原文件。局部修图使用原始字节。
- CloudBase 消费者对实测通过的 FluxPort `gpt-image-2.5-sunburst` 固定渠道优先发送 1 小时有效的私有对象签名 URL。压缩仍用同一编码，派生对象按素材复用并随临时参考图清理。签名或存储准备失败时，在首次提交前回退内嵌图片。供应商已经收到提交后，只查询原任务。上线消费者前应用 `20261105110000_private_provider_reference_jpeg.sql`，该迁移仅给现有私有桶追加 JPEG 类型。
- 2026-11-05 用两张相同的合成 PNG 对照，两组均完成真实异步生图，签名 URL 组保留了参考图中的独立标记。供应商提交请求体从 116,926 字节降到 1,350 字节（98.85%）。首次写入派生对象和供应商从存储取图仍产生流量。实际费用以各计费项的用量为准。
- 会话校验不在实例内缓存：停用账号和撤销须在下一次请求生效，见[企业登录](enterprise-auth.md)。

定时器：2026-11-01 01:42（上海时间）按用户要求将 `lycobo-outbox-minute`（每分钟）替换为 `lycobo-outbox-3h`（`0 0 */3 * * * *`），共享 PG 的兜底计量约 115 点/天。生成依赖 API 唤醒与消费者续排：唤醒需要 CloudBase API Key 调用函数的权限和 `TCB_QcsRole` 的 SCF Invoke 权限，须以线上日志为准（无 `CONSUMER_WAKE_FAILED`、`CONSUMER_CONTINUATION_FAILED`）。唤醒失败时任务最长等到下一次 3 小时兜底，有人查看排队任务时 API 每 15 秒补唤醒一次；如线上确认唤醒不可用，应恢复每分钟触发器 `0 * * * * * *`。

### 空闲数据库访问控制

前端共享 QueryClient 不再因切回标签页或网络重连自动重查过期查询，避免没有任务时集中访问会话、历史、钱包和素材接口而唤醒共享 PG。首次加载、重新挂载页面的过期查询、提交/重试/删除后的显式失效，以及可见页面中的未完成任务轮询继续执行；实际业务请求仍逐次进行服务端身份与归属校验，不缓存授权结论。其他设备的历史/余额变化需要重新进入相关页面或刷新页面同步。

任务轮询先按查询缓存更新时间合并同一任务的快照，再筛选排队/执行中状态，避免旧历史页或旧详情缓存持续轮询已结束任务；更新后的显式重试仍可被轮询。服务器明确返回 404 时，从已加载历史及详情缓存移除该任务，防止后续历史重载失败造成永久空查；网络错误不移除任务，继续退避恢复。

## 图片读取与下载优化

- 普通图片 GET 直接读取对象流和响应元信息，不再先执行一次 HEAD；客户端 HEAD 仍只读取元信息。适配器透传 GET 的 ETag，条件请求返回 304 时关闭未使用的响应流。
- 历史记录已有的签名链接在剩余有效期超过 60 秒时继续用于批量下载；缺失或临近过期的链接通过 `POST /api/v1/image-assets/deliveries` 一次补取（每批最多 100 个）。服务端使用当前身份和组织范围批量查找对象，仅返回可访问素材，客户端在任何素材缺失时中止打包。打包仍顺序读取原图，保留原有内存上限、取消及总超时。
- 单图签名失效时回退 `/image-assets/:id/content?download=1`，重新验证归属后跳转原图下载能力，不能回退成 WebP 预览；旧版预览/缩略图接口兼容保留。
- CloudBase `lycobo-assets` 校验既有来源、精确对象、到期时间与 download 签名后，调用 PG `POST /v1/storages/object/sign/{bucketId}/{objectName}`，返回 302 到平台短期 URL。有效期最多 300 秒且不超过当前应用签名剩余时间；跳转响应 `private, no-store`，平台 URL 使用 `download` 参数指定原 PNG 文件名。预览和缩略图继续走现有浏览器私有缓存；本地 S3 仍流式读取原图。
- 视频播放同样不经函数转发（云函数响应体上限6MB）：校验 preview 签名后 302 到不带 `download` 参数的平台短期 URL，有效期最多15分钟；是否支持 Range 待首次部署验收，见[视频接入](video-generation.md#封面与播放)。
- 平台签名链接是短期持有者凭证，在有效期内可由持有者访问，不再次经过应用来源校验。桶仍为私有，不新增公开读或列目录权限。签名请求固定环境网关、禁止跟随重定向，返回 URL 必须匹配当前网关与原对象路径，服务端 API Key 不下发、不记录签名 URL。签名服务失败不回退公开地址。
- 接口依据：[PG 签名接口](https://docs.cloudbase.net/http-api/storage-pg/获取预签名下载链接)、[签名访问与下载](https://docs.cloudbase.net/storage/pg/serving)。已对现有对象做只读验证：授权直读与签名 GET 的 SHA-256 一致、附件下载和网站 Origin 的 CORS 正常、无效与过期 token 返回 401。未改线上函数或存储配置；代码需正常发布后生效。

### 预览缓存与来源限制

预览／缩略图签名按15分钟窗口签发，剩余有效期23小时45分至24小时；浏览器使用 `private, max-age=剩余秒数, immutable`。原图下载的应用签名继续30–45分钟，平台跳转签名最多5分钟。前端分别读取预览和下载 URL 的过期时间，更新下载链接不会替换仍有效的预览。接口 `expires_at` 保持为最早到期的下载时间，兼容尚未刷新的旧前端；新前端按预览 URL 的签名期限维护展示缓存。

标签页 sessionStorage 最多保存200组预览链接（不保存下载链接），按组织和用户隔离；刷新后必须先通过正常业务接口拿到已授权素材元数据，且当前资源域名、路径、用途匹配，才复用旧预览 URL。过期／换源不复用，登录、退出登录和图片失败刷新时清理；存储被禁用时降级为内存缓存。缓存不包含登录凭据。

当前仍为私有图片函数链路：Origin／Referer 白名单和签名验证先于对象访问。没有把响应改为公开共享缓存，也没有开启云端 CDN 的7天缓存；CloudBase 官方 PG CDN 文档未提供本应用自定义 HMAC 在默认域名缓存命中前验证的配置。浏览器缓存优化可减少刷新重新下载，但不能声称已接入共享 CDN。后续接入需验证边缘鉴权，不能通过忽略签名参数或公开桶绕过私有权限。长有效期签名及已下载的浏览器缓存不能即时撤回。
