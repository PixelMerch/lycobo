# 家纺主图裂变

## 已实现的流程

入口 `/commerce/textile-set`。主图必填1张，详情图可选最多5张，支持多选与分批追加、单项替换／删除和清空全部详情图；用户选择1–10个不同视角及比例。张数由视角数量确定，不新增模型／提示词／质量／张数控件。固定 `gpt-image-2.5`、1K、标准质量，每张20积分。按钮显示总积分；确定失败逐图退款，未知收费结果按既有核对流程处理，不自动重复付费请求。

提交使用现有 `/image-assets`、`/image-tasks`：上传仅发生在点击生成后，第一参考为主图、第2–6张参考为详情图。静态角度示例从不作为参考图提交。鉴权、组织归属、幂等、任务与outbox事务、账本、存储路径和签名CDN沿用原链路。

一个任务包含N个子任务，对应N个有序视角。API在保存前替换客户端提示词、模型、质量、分辨率为服务端固定配置；Worker按子任务的稳定position读取视角预设，各请求 `n=1`，得到独立单图，避免一个多图请求重复同一构图。模板包含商品身份／颜色／花型／绗缝保留、详情图辅助规则、视角构图及禁止拼图文字水印；实际模型还原程度需真实图片验收，不能保证所有材质和花型都完全一致。

模板在 `packages/generation/src/textile-generation.ts`，元数据 `textileSet.version` 和有序views保存在既有任务input。v1保留原1张详情图规则；当前提交使用v2，允许最多5张详情图且明确所有详情图仅辅助材质／花型。v1预设保持稳定，旧任务仍按v1解析和重试；后续修改语义须新版本，保证重试仍按原版本执行。供应商模型ID继续通过现有分辨率路由确定。

## 历史与重试

`GET /image-tasks?tool=textile` 只分页裂变任务，`tool=create`只分页普通创作；省略tool保持旧的全部任务语义。筛选在数据库limit之前执行，不用前端过滤已分页结果。共享历史组件按工具使用独立缓存，SSE同步更新所有已加载历史缓存。当前图的角度按item.position映射，部分失败仍保留其他成功图片。

重新编辑恢复1张主图和全部详情参考、视角和比例，不覆盖创作模型草稿。重新生成沿用任务确认弹窗；失败卡片hover／键盘聚焦提供单图重新生成，触屏常显，确认单张费用后调用现有retry接口并传itemId，只重试当前失败或待核对条目；任务头部入口不传itemId，仍批量重试失败项，成功图片保留，position不变。响应丢失时保留原请求与幂等键，刷新后“确认上次提交”原样重放，不能因为用户修改当前输入而新扣一次。

## 迁移与部署

- `0016_textile_generation_count` 将generation_jobs容量扩展至10张，大于4张必须含textileSet元数据；普通创作输入契约仍最多4张。
- `0017_textile_item_positions` 将generation_job_items的position扩展至0–9。
- `0018_targeted_image_retry` 为既有generation_retries增加可空target_item_id外键，将单图重试的幂等键绑定到目标图片；NULL保持旧批量重试语义。同键换图被拒绝。
- 没有新业务表，没有修改旧迁移，也不使用db push。新增元数据可选，旧任务解析与幂等hash保持不变。
- 本轮仅迁移本地开发库；线上尚未部署。发布时先执行上述迁移，再更新API与消费者，最后启用前端。旧消费者不理解视角元数据，不能让旧消费者领取新裂变任务；同仓发布也要遵循此顺序。
- 共享契约、数据库约束和两条SQL迁移需在后续PR显式审核。

## 验证边界

本轮自动验证使用隔离PostgreSQL、临时图片存储、原有Queues/R2/Images模拟，以及注入的服务商fixture。不会调用外部付费模型，不写线上业务数据。真实床品主图的模型质量尚需使用明确测试账号与限额人工验收。
