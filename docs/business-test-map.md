## 优先补充的组合故障验证

以下场景未从本次抽查得到完整证据，属于待验证项，不代表已经发现生产缺陷。先沿现有测试入口追查是否已有等价断言，避免重复建设。

1. **回调与查询同时完成**：用同步屏障并发触发同一尝试的两个结果入口，核对最终结果、结算流水与事件数量；不能只测重复调用同一个 finish。
2. **存储成功、数据库完成前中断**：在对象写入后注入失败，再执行恢复；核对不重复请求付费模型、结果对象能够重用或有明确清理策略、任务与账务最终一致。
3. **数据库完成、Queue 确认前中断**：模拟同一消息重投，核对不再次扣费、不重复发布完成通知；现有 claim 互斥测试不能代替该场景。
4. **持久回放与浏览器补齐组合**：断开连接期间完成任务，恢复连接并重复交付事件；核对积分、消息、完成提醒一致，草稿与当前路由保留。

这些验证应扩展隔离数据库、loopback provider 与对象存储 fixture，不使用生产数据库或付费模型。实现前读取相关目录规则；涉及 SQL 或数据库测试时先加载 PostgreSQL 技能。新增断言通过后更新本表的证据范围，不把计划提前改成已覆盖。

## 最小阅读顺序

AI 接手某一规则时先读本表对应行，再读链接中的断言、被测实现与调用方，最后选择[测试命令](testing.md#按改动选择验证)。涉及计费、权限、重试时必须追到仓储事务，不能仅依据测试名判断行为。交付记录实际命令和对应提交；无需复制完整日志到本文。
