# 模型服务后台与执行适配

2026-10-27 实现，本轮仅本地部署、Docker PostgreSQL 建表和隔离验证，未更新线上。

## 入口和职责

独立后台仓库 `../lycobo-admin`，Docker 页面 `http://localhost:8082/#model-services`，登录 `http://localhost:8082/login`。主站 API 仍负责身份、平台授权、配置持久化和任务执行；后台 Node API 以同源 HttpOnly Cookie 代理受限的管理接口。浏览器不接触供应商 Key、上游请求和数据库。

本地已有企业账号 `17521204070` 已单独授予平台管理权限。企业主账号角色本身不等于平台管理员；生产必须另行授权。既有其他后台业务页面仍为演示，模型服务页面是真实数据库读写。

## 配置顺序

1. 中转站：填写名称、HTTPS 源地址（例如 `https://api.ai-media.vip`，不含 `/v1`）、协议、API Key 和启用状态。新建默认禁用。Key 写入后只显示“已加密保存”；编辑留空保留旧 Key。
2. 模型渠道：选择中转站、前台模型、任意合法上游模型 ID、执行方式、参考图能力及上限、分辨率、提交超时、总等待上限和额外结果下载源。
3. 默认渠道：按图片创作／家纺主图裂变／局部修改及前台模型绑定一个渠道；同一前台模型可以在不同功能使用不同渠道。禁用的绑定停止新任务，不自动回落到其他付费服务。

前台公开模型仍为 `gpt-image-2`、`gpt-image-2.5`、`nano-banana-2.1`，读取服务端能力；上游实际名称独立配置，例如家纺渠道可填写 `gpt-image-2-4K`。尚未绑定的组合继续兼容原环境变量渠道，并不自动启用新站。

协议支持 OpenAI 兼容图片同步协议（文生图 JSON、参考编辑 multipart）和 FluxPort 图片协议（JSON 参考图、同步或异步）。执行方式可选同步、异步优先、供应商默认；即使异步优先返回同步图片也能接受。新站使用相同协议时只填配置；不同任务路径／鉴权／响应格式仍需要新增服务端适配器，不允许后台填写可执行脚本。

“检查连接”仅请求 `/v1/models`，不发起付费生图，也不证明模型、额度或参考图能力已经验证。某些供应商没有该接口时不能凭连接测试判定无法生图。

## 密钥和数据库

服务器必须配置 `MODEL_CREDENTIAL_SECRET`：32 字节随机数的 Base64；API 与生成 Worker 使用相同值。生成示例：`node -e 'console.log(require("node:crypto").randomBytes(32).toString("base64"))'`。本地在忽略的 `.env` 保存，开发 setup 传入两个 Worker；不得放入 `VITE_*` 或 Git。当前本地已配置。

Key 使用 AES-GCM 加密，版本记录不可被后台覆盖；换 Key 新建版本，在途任务仍使用原版本。主密钥需独立备份，直接更换会使旧记录无法解密；本轮不实现主密钥轮换。生产发布前需单独迁移数据库，并设置 API／Worker 的 Secret；本次未操作 Supabase。

Drizzle 迁移 `0019_model_channels`、`0020_model_configuration_rls`、`0021_provider_poll_failures` 已应用本地 Docker：

| 表 | 用途 |
| --- | --- |
| platform_administrators | 平台管理员授权 |
| model_providers | 中转站及当前密钥版本引用 |
| model_credentials | 加密密钥版本 |
| model_channels | 上游模型、协议执行配置和能力 |
| model_routes | 功能与前台模型到默认渠道的映射 |
| model_audit_events | 操作者、动作、记录 ID 和时间，不存 Key／提示词 |
| provider_executions | 子任务异步 ID、查询路径、租约、截止时间、连续查询失败次数 |

`generation_jobs.provider_snapshot` 固定已接收任务的渠道、上游名称、能力与密钥版本；公共任务返回值不暴露该字段。新增表开启 RLS，不向匿名／普通用户提供策略；服务端通过受控数据库角色操作。

## 异步任务和计费

任务、积分和 outbox 事务仍是唯一提交入口，每个视角一个子任务。异步 POST 只执行一次；202 后保存 task ID、同源查询路径和下次查询时间，结束本次消费。通过现有 outbox 维护及 Cron 再次调度 GET 查询，不在 Worker 长时间等待。当前调度存在维护间隔／Cron 粒度，并非毫秒级实时轮询；`poll_after_ms`、`Retry-After` 和指数退避决定最早查询时间。

查询成功后拉取真实文件并保存到私有 R2，再完成任务；摘要里的 `result_url` 作为任务 JSON 结果接口继续查询，不当作图片下载。结果下载仅允许源站和显式配置的 HTTPS 下载源；Key 不发送到第三方 CDN，拒绝重定向。

明确失败进入现有退款流程；请求结果不确定、查询停止、总等待超时进入待核对，不能自动重复付费提交。连续查询网络／限流／服务错误最多五次后停止自动处理。保留原有人工核对及用户明确确认的重试语义。不会因为刷新后台、修改配置或队列重复投递重复扣款。

本轮未实现 webhook、自动跨站重试、自动价格同步、任意新增前台模型或供应商真实生成验收。

## 验证

`pnpm check`、本地 opt-in `pnpm test:integration`，异步适配和加密单元测试；独立后台 `pnpm check`；浏览器验证登录、写入中转站／模型渠道、默认渠道编辑和 Key 不回显。隔离执行使用 fixture，不调用新的付费模型。临时界面验收配置在结束后移除。
