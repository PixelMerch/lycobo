# 账号设置功能任务书

日期：2026-11-05。状态：待开发与验收。用途：交给 Claude Code 在本仓库实施。

本任务书记录本次新增需求，不代表功能已经上线。开发遵守根目录及相关目录的 AGENTS.md；产品基础见 [PRD](../PRD.md)，视觉沿用 [DESIGN](../DESIGN.md)，架构见 [PROJECT_STRUCTURE](../PROJECT_STRUCTURE.md)。本次只补齐账号设置相关功能，积分与账单按现有逻辑保留。

## 1. 目标与范围

- 个人资料显示真实头像、昵称和账号身份；用户可以上传头像、修改昵称。
- 属于企业的用户显示“企业用户”标识、企业名称和企业内角色。
- 企业管理员可以在设置内添加成员，由系统生成登录账号和随机初始密码，并支持复制交付。
- 新成员首次登录必须进入个人中心重置密码，完成后才能使用业务功能。
- 用户可以绑定微信，绑定后下次使用微信登录仍进入同一个账号。
- 用户可以修改密码；保留现有密码校验和全部设备会话撤销规则。
- 手机号登录用户的默认昵称为手机号；微信登录用户的默认昵称为微信授权返回的昵称。
- 积分与账单的入口、查询、共享余额、扣费退款、筛选和订单逻辑保持现状。

“个人中心”在本任务中指现有“设置 → 登录与安全”。复用独立设置弹窗，不新增一级导航或另一套个人中心页面。首次改密使用这个位置承载强制流程。

## 3. 个人资料

### 3.1 展示与同步

- 展示头像、昵称、UID 和登录账号；昵称是显示名，登录账号仍是独立标识，改昵称不改变登录凭据。
- 企业用户额外显示“企业用户”、真实企业名称、企业管理员或企业成员。普通个人账号不显示企业标识；不得编造企业名称。
- 设置、侧栏账户胶囊、账户菜单和账单中共用的账号信息展示，应读取同一份服务端资料。修改后无需重新登录即可同步；刷新或换设备后仍有效。
- 没有头像或头像加载失败时沿用现有回退样式；没有可用昵称的历史账号回退到登录账号，不显示空白。
- UID 沿用现有十位数字字符串及复制能力，不作为登录账号或授权依据。

### 3.2 昵称规则

| 用户来源             | 首次初始化昵称                     |
| -------------------- | ---------------------------------- |
| 手机号认证登录       | 已通过服务端验证的手机号           |
| 微信认证登录         | 微信授权返回的有效昵称             |
| 管理员创建的企业成员 | 系统生成的登录账号，之后由本人修改 |
| 已有企业账号         | 没有昵称时回退现有登录账号         |

- 昵称默认值只在初始化或历史缺省兼容时使用。用户主动修改后，后续登录或绑定微信不得覆盖。
- 微信昵称缺失、空白或无权获取时回退到已有昵称或登录账号，不将该用户登录直接判失败。
- 建议本期昵称校验为去掉首尾空白后 1–32 个字符，支持中文，不要求唯一；前后端使用一致的字符计数和校验。此为实施默认值，不是已有契约。
- 保存中防止重复提交；成功展示服务端结果，失败保留输入并显示真实错误。

### 3.3 上传头像

- 用户选择本地图片，上传成功并保存资料后替换头像；取消选择不变更资料。
- 建议本期支持 JPEG、PNG、WebP，文件不超过 5 MiB；不增加必须裁剪的流程。以上为实施默认值。
- 服务端检查文件大小、真实格式和可解码性，限制像素总量，去除元数据并生成适合头像展示的尺寸；拒绝 SVG、伪造格式和异常图片。
- 文件进入现有私有存储体系；资料保存稳定资源标识，不保存临时签名 URL，不把对象桶改成公共读。
- 头像读写按当前用户授权；同企业成员也不能修改他人头像。上传或保存失败保留旧头像，失败产生的未引用对象应可清理，避免误删仍使用中的对象。

## 4. 企业成员管理

### 4.1 权限和列表

- 仅企业管理员显示“企业成员”页签和添加入口。服务端每次校验当前用户的真实组织成员关系及管理员角色。
- 管理员只能查看和添加本企业成员。企业内普通成员无管理权限；隐藏按钮之外还必须拒绝直接请求。
- 列表至少显示昵称、登录账号、角色、首次改密状态和创建时间；读取真实数据库。列表超出一页时复用现有滚动分页规则。
- 本期添加的成员固定为普通成员，不开放前端指定组织或提升管理员权限。
- 移除成员、停用账号、转移管理员、管理员重置成员密码和席位购买不在本次范围。

### 4.2 添加、生成与复制凭据

1. 管理员点击“添加成员”，提交一次创建请求，账号由服务端生成，符合现有账号规则且全局唯一；唯一性冲突由服务端有限重试。
2. 服务端使用密码学安全随机数生成初始密码，满足现有 12–256 字符要求。数据库只保存哈希。
3. 在一个事务内创建用户、企业成员关系、登录凭据及“必须重置密码”状态；失败全部回滚，不产生半成品账号，不新建企业钱包。
4. 成功后显示创建结果，提供“复制账号”“复制初始密码”和“复制账号与密码”。组合文本包含明确的账号与初始密码标签，方便管理员交付给成员。
5. 复制成功有提示；剪贴板失败保留可手动选择的内容。管理员主动复制之前不自动写剪贴板。
6. 关闭创建结果后清理前端明文密码，不在普通成员列表、后续查询或重新打开设置时提供密码回显。

创建提交防重复；服务端通过幂等机制保证双击、并发或响应丢失后重试不会创建多个成员。明文密码只在首次成功响应的短生命周期结果中展示，不存日志、审计正文、浏览器持久存储或可恢复的明文凭据表。响应丢失后按请求标识确认是否已创建，不盲目重建；已创建但凭据未交付时明确提示需走受控重置流程，本期可沿用既有受控账号脚本，不伪造“可再次查看原密码”。

## 5. 新成员首次登录强制重置密码

- 使用随机初始密码认证成功后，服务端返回“必须重置密码”状态，前端立即进入设置的“登录与安全”，突出“首次登录，请设置新密码”。这一步是受限登录，不等于业务权限已开放。
- 强制改密状态必须持久化。刷新、续期、关闭弹窗、改地址、打开新标签页或直接调用 API 都不能绕过。
- 门禁在业务请求授权处统一执行；待改密状态只放行必要的身份查询、续期、改密和退出。不得创建付费任务、上传业务素材、读取企业账单或企业业务数据。
- 强制流程不提供返回业务页的关闭方式，但始终允许退出登录。桌面、移动端和键盘操作都可完成。
- 输入当前初始密码、新密码和确认新密码；新密码符合现有 12–256 字符要求，且不能与当前初始密码相同。
- 验证成功后，在同一事务中更新密码哈希、清除强制改密状态、更新凭据版本并撤销该账号全部会话。失败不清除强制状态。
- 沿用现有改密成功后重新登录的行为：清理当前会话与敏感缓存，提示使用新密码登录；新密码再次登录后恢复正常权限。
- 已有正常账号不会因新增字段被统一强制改密；仅本次新建成员或被明确设置为待改密的账号进入此流程。用户未提交的创作草稿仍按现有规则保留，不能因改密丢失。

## 6. 微信绑定、后续登录与修改密码

### 6.1 绑定微信

- 已登录用户在“登录与安全”查看微信绑定状态；未绑定时可发起真实微信授权，已绑定时显示绑定状态和可获取的微信昵称。
- 授权回调必须校验服务端生成、短期有效且一次性使用的 state，并关联发起绑定的用户与会话，防止串号和重放。
- 由服务端用微信返回的授权结果换取并核实身份；不能接受浏览器自报的昵称、OpenID 或 UnionID 作为绑定证据。
- 同一微信身份只能绑定一个站内用户；若已绑定其他账号，返回明确冲突，不自动合并用户、企业、作品或钱包。
- 绑定成功后保持原 `userId`、UID、企业关系、权限和钱包归属；已有昵称和头像不因绑定被覆盖。
- 用户取消、授权过期、回调失败时保留原账号，允许重新发起授权；不能显示虚假绑定成功。
- 本期不新增解绑、换绑或自动跨账号合并流程。

### 6.2 下次微信登录

- 退出后可从现有微信登录入口完成真实授权，服务端查找已绑定用户，签发既有体系的会话；仍校验账号状态、组织关系和强制改密状态。
- 登录必须回到绑定的同一账号，不创建重复账号或额外钱包；待改密账号不能借微信登录绕过第 5 节门禁。
- 未绑定微信的登录结果不得自动创建企业用户或赋予企业权限。本期默认提示先使用现有账号登录并绑定；如要支持独立微信注册，应另行确定注册及个人账户初始化规则。
- 微信首登初始化昵称规则适用于未来允许的真实微信新用户或确实缺省的资料，不能用于覆盖已有用户资料。

### 6.3 修改密码

- 有密码的账号继续输入当前密码、新密码、确认新密码；确认密码仅用于前端校验。
- 验证旧密码错误时保留会话，显示真实错误；成功后所有设备的访问和刷新凭据失效，当前设备清理登录态并要求重新登录。
- 微信绑定不改变原有密码登录能力，也不能用于绕过旧密码校验。
- 未来仅以手机号或微信注册且没有密码的用户，应通过已验证身份的独立“设置密码”流程处理，不能填写虚构旧密码或直接套用改密接口；该注册与验证流程不在本期默认范围内。

## 7. 外部依赖与实施边界

- 当前手机号短信登录没有接通。本期定义默认昵称及其初始化位置，不把“账号字符串看起来像手机号”视为手机号已认证；完整短信发送、验证码登录、注册和找回密码另行排期，不阻塞已有企业账号资料与成员功能。
- 微信绑定和已绑定账号的微信登录属于本期目标。实施前核实项目采用的微信平台类型、网页扫码方式、可用授权范围、昵称获取权限、应用凭据和回调域名，查阅对应官方文档。现有“公众号扫码”文案不能作为实际可用能力的证明。
- 如果微信平台条件或凭据缺失，先完成其余可验证部分，记录准确缺项；微信功能标记为待外部联调，入口按真实能力开关控制。不能用静态二维码、测试昵称或内存绑定结果宣布完成。
- 不在本次任务中购买服务、配置生产平台、执行生产迁移、发布或发送成员凭据。实际部署和对外发送信息需另外明确授权。

## 8. 积分与账单保留要求

- 保留当前独立“积分与账单”弹窗，仍为“积分明细”“充值订单”两个页签；设置继续独立打开。
- 保留企业共享钱包，管理员与成员使用同一企业余额。添加成员、上传头像、修改昵称、绑定微信、修改密码均不扣费、不赠送积分。
- 保留现有只读接口：`GET /api/v1/wallet`、`GET /api/v1/wallet/entries`、`GET /api/v1/wallet/recharges`，及现有授权范围、游标分页、筛选和缓存失效机制。

| `apps/api/scripts/enterprise-account.ts`                                               | 既有受控创建/重置工具，不能作为公开成员接口直接暴露    |
| `tests/e2e/account-settings.spec.ts`、`account-menu.spec.ts`、`account-center.spec.ts` | 既有交互回归入口                                       |

新增接口路径和字段在实现时按现有领域命名确定，本任务书不宣称已有新接口。所有 JSON 继续由 createApp 统一包装 `request_id/code/message/data/error`，新增错误码在 contracts 登记；路由保持薄层，业务和持久化分离。业务权限来源于服务端身份，不能信任请求中的组织 ID、用户 ID 或对象 key。Cookie 写请求沿用可信 Origin/CSRF 防护；凭据、授权码、Token、签名 URL 和原始微信响应不得写日志。

| ------------ | ----------------------------------------------------------------------------- |
