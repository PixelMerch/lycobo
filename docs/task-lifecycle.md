# 异步任务与恢复设计

本文是业务实现契约，初始化只创建 schema 和接口，尚未实现完整流程。

## 状态与持久化

任务：queued → running → succeeded / partially_failed / failed / cancelled。
结果项单独记录 queued/running/succeeded/failed/cancelled；
任务结果由已完成项聚合，完成数量与 requested_count 对齐。
viewed_at 是用户是否查看结果，独立于执行状态；archived_at 是归档，不是删除。
取消请求与实际取消结果要分开设计，不能承诺已取消仍在远端运行的付费任务。
未来增加状态必须同步 contracts、数据库迁移、Worker 和前端映射。

## 提交

- 服务端认证并验证 owner/project/asset 归属、限额、输入和模型能力。
- Idempotency-Key 对同一 owner 唯一；相同 key + 相同 payload 返回原任务。
  相同 key + 不同 input_hash 返回冲突，不能静默换参数。
- 单个数据库事务写 task、结果项、必要的预留计费流水、outbox。
- 事务提交成功后返回 202 与 taskId，前端立即可以提交下一件商品。
- dispatcher 以短事务 claim 待派发事件，使用确定 jobId 入队；失败后可恢复。
  禁止在长事务中等待模型或 OSS。
- 至少一次投递是现实前提；消费者必须幂等，而不是声称 exactly once。

## 服务商调用与重试

保存 providerTaskId，设置超时与 AbortSignal，按服务商/账户限流。
同一服务商批量任务可能返回多张图，多个结果项允许共享 providerTaskId；
结果去重依赖本地 taskId + position 与回调事件键，不能把远端批次 ID 当单图唯一键。
超时不等于没有提交；先查询或凭幂等键对账再重试，避免重复付费。
只重试失败项；用户主动“再生成”创建新任务，不改写旧参数和原图。
回调需要签名校验、重复事件防护和合法状态转换。

## 结果保存

不要直接将服务商临时 URL 当永久作品地址。
受限下载 → 验证格式/大小 → 私有存储 → 生成缩略图 → 事务更新结果和通知。
生图成功但保存失败应进入可恢复处理阶段，不丢弃已付费产物。
输出对象 key/元数据可以持久化，签名下载 URL 只在读取时按权限生成。

## 通知与找回

任务中心从 PostgreSQL 分页查询，不从 Redis 历史拼成用户记录。
完成/失败通知与结果变化原子记录，eventKey 去重。
SSE 推送只作及时提示，断线后用持久事件游标或重新查询补齐。
新结果数量与任务/通知的读取规则统一，不能在 toast 消失时自动标为已读。
关闭页面不会取消任务，也不删除项目；重新登录可继续查看。

## 计费与画布（后续）

积分预留、扣除、释放和退款分别用不可变流水与唯一业务键建模。
画布保存 assetId 与位置/缩放，不存签名 URL 或图片 base64。
canvasVersion 用于乐观并发更新；检测冲突，不能让后到请求覆盖其他人的编辑。
数据库基础字段已预留，但尚未接入这些业务 API。
