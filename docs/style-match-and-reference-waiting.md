# 工具预览、复制爆款与后台参考图处理

2026-11-10 用户确认的本轮范围：主图制作、家纺裂变、套图计划保留原名；新增复制爆款；隐藏视频入口，不开放视频生成。

## 复制爆款

`/:locale/commerce/replica` 使用独立草稿和历史。目标图作为版式模板。生图模型在同一次请求中根据模板画面识别实际存在的商品、标题、说明、徽章与特写，按原位置和视觉层级重现。参考图提供替换商品，模板中同一商品的特写与重复呈现一起替换。文字沿用原排版与语言，只有适用且有依据的商品参数才保留，不凭空补写。目标图1张、商品参考图最多10张，提交顺序固定为风格、商品，角色为 `style`、后续均为 `product`。每张参考图独立生成1张结果，单条输出只发送目标图和对应参考图，避免混入其他商品；费用为参考图数量×2积分，目标图不计费。固定使用 `gpt-image-2.6-sunburst`，不展示模型与张数选择。补充要求支持与主图制作相同的流式优化与撤销，优化另按现有1积分规则计费，不新增分析模型调用。

`imageGenerationInputSchema.replica` 为可选的 `true` 标记，仅新任务携带；旧输入与幂等哈希不变。服务端强制2至11张不同参考图、正确角色、生成数量等于商品参考图数量及互斥工具输入。标记随 PG 任务快照持久化，用于历史、素材来源、重新编辑、重新生成与完成消息定位。不保证销售效果；示例不代表用户结果。

图片任务的 `generation_jobs.user_prompt` 独立保存最终提交的用户文字，复制爆款在拼接模板和转换参考图编号前取值。历史和素材展示读取该字段，空字符串代表未填写。模型仍使用 `prompt` 和 `input` 中的生成输入。迁移 `0046_user_prompt` 回填已有图片任务，复制爆款提取模板首行之后的补充要求，旧家纺任务回填为空，其他图片任务沿用已提交的正文。上线先应用迁移，再部署读取新列的代码。

## 参考图与生成任务的持久衔接

1. 浏览器沿用共享压缩上传，原图与私有上传意图落到 R2 后获得 `uploadId`。原始文件传输尚未完成前，不能承诺关闭页面后继续。
2. 收到上传票据后直接提交生成任务，不在浏览器中轮询处理完成。素材 ID 与票据 ID 相同。
3. API 在事务外按当前身份验证私有 R2 上传意图。只有服务器验证为 pending 的 ID 才传给内部仓储的接收名单，客户端不能提供该名单；其他参考图仍必须存在于本组织的有效素材中。
4. PG 在同一事务保存任务、扣费与 outbox。返回成功后可关闭页面。Queue 在领取供应商执行前查询该持久任务的缺失素材，并核对 R2 意图状态；待处理时延迟 15 秒重新检查，不领取、不创建供应商尝试、不调用付费模型。
5. 图片完成后正常入素材库。已被任务引用的参考图改为长期保存，避免任务先提交而素材后落库导致三天后失效。
6. 确定失败、意图失效或任务等待超过 15 分钟时，沿用任务结束与幂等退款，不盲目重投付费请求。Queue 延迟消息与 PG outbox/Cron 共同补偿，不依赖页面在线。

没有新增数据库表或迁移。R2 上传意图只用于未付费文件处理，PG 仍是任务、扣费和 outbox 的真相源。沿用现有图像服务端格式校验、上传归属和参考图授权。

## 发布与验证

共享契约增加可选标记及工具枚举，发布时先更新图片消费者，再更新主站（API 与前端一起）。不可先发布依赖待处理素材接收行为的前端。旧已部署版本不会因本地修改而自动变化。

`pnpm check` 检查代码质量、类型、单元测试和构建。隔离图片集成新增 `verifyReplica` 和 `verifyReferenceWaiting`，验证工具隔离、归属拒绝、一次扣费、待处理时保持 queued、素材完成后长期保留与失败退款。CI 的 `tool-preview-replica.spec.ts` 使用 API fixture 检查双图必填、角色顺序、202 后无需查询上传状态即可提交、草稿保留、键盘预览和减少动态效果。未以真实付费模型验证生成质量。

批量复制依赖追加迁移 `0045_replica_batch_count.sql`；发布时先执行数据库迁移，再部署图片Worker，最后部署主站。该迁移只扩展计数约束，不改写已有任务。
