# 页面语言路径

页面使用 `/zh-CN` 与 `/en` 前缀，首页分别为 `/zh-CN`、`/en`；工作台示例为 `/zh-CN/commerce/create`。电商专区示例为 `/zh-CN/commerce?tool=textile`；工作区快捷入口为 `/zh-CN/workspace`，恢复最近使用的电商工具。

## 规则

- URL 明确的语言优先于本机偏好。无前缀入口先使用已保存的选择，再按浏览器语言选择；原页面、查询参数与片段保留。首次访问在路由初始化前补齐地址，不额外刷新页面；后续无前缀导航由父级 loader 规范化。
- 语言作为同一套路由的父参数，不复制中英文组件。切换语言保留当前页面、查询参数、片段、history state 和滚动位置；浏览器前进后退同步语言。语言变化不重建应用壳、输入框、草稿或实时传输。
- `RouteLink` 自动生成当前语言链接。命令式页面导航使用 `useAppNavigate`，点击时读取最新语言，避免任务完成提醒捕获旧语言或因语言变化重新订阅。
- 工具选中、公开页门禁和工作区偏好仍使用不带语言的业务路径，由 `useAppLocation` 提供。`pathnameWithLocale` 保留真实地址，供登录返回等用途使用。不要给业务工具常量逐个硬编码语言。
- 非 React 的纯地址处理使用 `i18n/locale-path.ts`。登录返回仍按允许的业务路径校验；语言前缀不是授权依据，外站、登录循环、旧 `/create` 以及 API 地址仍不能作为登录返回页。
- `/api`、WebSocket、图片、字体及其他静态资源保持原始根路径，不附语言；数据库的任务标识、积分、素材与模型请求不随语言改变。任务结果路径在用户点击时由页面导航层补齐当前语言。
- 仅更换语言不重复定位已显示的历史任务；真正换任务或主动重新打开结果仍按正常导航定位。

## 维护与验证

路径转换、登录返回权限和历史定位有单元测试。CI 的 `locale-routing.spec.ts` 验证显式语言优先、草稿及输入框节点保留、参数与片段保留、前进后退、实时连接数量不变、受保护地址进入同语言登录页及 API 不加前缀；`language.spec.ts` 验证中英文与手机语言入口。

公开站点仍保留现有 `noindex,nofollow`。本次建立可分享的语言地址，没有解除索引限制，也没有实现服务端多语言 HTML、canonical、hreflang 或 sitemap；正式开放搜索收录时需要单独完成这些配置与验证。
