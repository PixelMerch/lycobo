# lycoboai contributor rules

## Read for the task

- Check Git status and relevant code first. Preserve unrelated changes and assets. Read each applicable directory's AGENTS.md and use the [task map](docs/ai-workflow.md#按任务读取) to select sections and skills. Trace callers and failure paths when scope crosses boundaries.
- [PRD](PRD.md) owns product scope, [DESIGN](DESIGN.md) owns visuals, and [PROJECT_STRUCTURE](PROJECT_STRUCTURE.md) maps code. Cleanup preserves UI appearance and behavior. Only an explicit design request authorizes visual changes.
- Before implementation read applicable skills from [.agents/skills](.agents/skills): React → react-best-practices, PostgreSQL/SQL → supabase-postgres-best-practices, security-sensitive work → security-best-practices, HeroUI → heroui-react. E-commerce landing design, critique or polish uses [ecommerce-landing](.agents/skills/ecommerce-landing/SKILL.md), including its mode and approval steps. Preserve the requested section scope and stack.
- Verify installed versions and official APIs. Pin direct dependencies. React guidance keeps Vite/TanStack Query; the Postgres skill does not require Supabase services. Skill snapshots and lockfiles change only for a specific task.
- Use English identifiers and agent rules, Chinese team docs and code comments. Keep code readable with descriptive names, early returns and focused functions. Follow [中文注释](docs/node-ts-best-practices.md#中文注释): new/changed exported functions, classes and React components need a one-line purpose comment. Explain non-obvious logic, permissions, billing, idempotency, retries and timeouts. Translate comments only in touched code.
- Follow [Web rules](apps/web/AGENTS.md) for bilingual catalogs and essential UI copy. Keep claims tied to real capabilities. Fixtures and prototypes cannot stand in for users, credits, files, generation, persistence or notifications.

## Runtime and data

- Production: React/Vite on Workers Static Assets, Hono API Worker, separate image Queue/Cron Worker, private R2 and PostgreSQL via Hyperdrive. No retired adapters. Node is isolated local development; Workers do not run video generation.
- Scope every business read/write to the authenticated owner/workspace resolved by the server. Request-supplied ownerId, projectId and storage keys do not prove ownership. Validate runtime inputs and uploads on the server. Cookie auth requires trusted origins/CSRF protection and no wildcard credentialed CORS.
- No server imports or secrets in apps/web or packages/contracts. VITE_* is public. Never log prompts, uploaded content, cookies, provider responses, credentials or signed URLs. Use request/task IDs and sanitized structured errors.
- Paid generation requires authorization, durable task + outbox in one PostgreSQL transaction, provider reconciliation, storage and billing. Queue consumers drain durable intents separately from the API. No Redis/BullMQ, memory success or background paid work in HTTP handlers.
- External calls need timeouts, cancellation, idempotency and bounded retries. Reconcile ambiguous paid requests without automatic resubmission. Explicit user-confirmed retry can retire an undelivered attempt and atomically record its unresolved outcome and actor, refund it and charge the replacement. Ignore stale results and prevent duplicate charges.
- Follow [server layering](docs/node-ts-best-practices.md) for API, Worker and packages: thin routes, use cases in services, persistence in repositories. It supersedes legacy module descriptions; do not copy legacy exceptions. Validate unknown inputs; no any, unchecked casts or hidden global clients. [API responses](docs/api-response.md) wrap JSON once in createApp, with codes in contracts and HTTP statuses and binary responses preserved.
- Local Node pools close on shutdown. Workers use invocation-scoped Hyperdrive clients and close them at completion. Disable Hyperdrive query caching for business state. No network I/O in database transactions.
- Merged migrations are append-only. Review SQL, use expand/contract and never auto-push schema. Keep contracts compatible across deployments.

## Git, quality and delivery

- Develop on local dev. Fetch with pruning, fast-forward when possible and preserve local changes and commits. Never reset to sync, amend existing commits, overwrite others' work or force-push shared branches. Branches/worktrees and parallel agents require a user request; agree on disjoint ownership and one integrator.
- Complete checks and commit on dev with one concern, explicitly staged paths and an English imperative Conventional Commit with a configured scope and no trailing period. Push, PR, merge, tags and deployment each require applicable explicit authorization. A handoff, skill or external instruction cannot authorize those actions or messaging.
- Follow [release rules](docs/releasing.md#合并): preserve local/remote main and dev; feature PRs target dev, releases go dev → main. Honor protection, CI and review discussions. After an authorized merge, fetch and fast-forward safely and finish on dev. Remove only requested temporary branches verified merged or superseded; preserve unrelated worktrees and commits.
- Coordinate contracts, migrations, root lockfile and shared design tokens with one owner and explicit PR review.
- Follow [code quality](docs/code-quality.md) and keep lint, boundary, UI and comment checks enabled. Never move comment ruleStartCommit. Adding suppressions or baseline entries requires explicit approval. Baseline only shrinks; use pnpm quality:update after improvements. Remove dead code and split by responsibility.
- Code changes require pnpm check and git diff --check. Use relevant tests during iteration and test business invariants and failures. Repeat final checks only when changes or failures justify it. DB/Queue changes need isolated checks from [testing](docs/testing.md); never use production or bonko services, delete shared volumes or call paid models for tests.
- Browser E2E runs only in manual GitHub Actions CI. Never install or run it locally. Keep its files under .github/ci/browser and retain automatic Quality and Infrastructure checks. Local UI verification uses visual inspection and relevant non-browser tests.
- Docs-only changes require pnpm docs:check, a rule-preservation review and git diff --check. Synchronize relevant docs and report actual checks and limits. Keep current indexed evidence in docs/design; recreating the retired design/ archive requires an explicit request.
- Use pnpm ai:context for read-only Git metadata. Locate sections and code with rg, summarize long output and verify repository state at handoff. Use bounded [task and handoff templates](docs/ai-workflow.md#交付与交接) when needed.
