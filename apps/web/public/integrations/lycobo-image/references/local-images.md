# 本地参考图

在豆包的「本地电脑」中，让用户选一次文件夹并确认该文件夹可用于定时任务。保存所选目录、文件选择规则和各套图如何使用参考图。后续运行读取该目录里的匹配图片。仅用户授权的目录可读。Agent 需要能在本地运行技能内的脚本并访问连接器，云端环境无法读取这台电脑的文件。

1. 每次运行先确定各套要用的参考图。文件夹可以包含更多图片，每套挑选自己的参考图，最多 5 张。多套共用的图只准备一次。只对本轮选中的文件执行 `python3 scripts/reference_files.py fingerprint <目录> <文件1> <文件2> ...` 计算原文件 SHA-256，接受目录内的相对文件名或绝对路径。将每个路径作为独立参数传入，保留返回的 `files` 在本地。文件改名但内容相同会复用原素材。
2. 调用 `prepare_reference_uploads`，只发送 `{ "fingerprints": [...] }`。同一批内去重，每次最多 100 个。命中项返回 `sha256`、`assetId`；未命中项返回 `sha256`、`uploadUrl`、`uploadToken`。整批都命中时直接用对应 ID，跳过脚本的上传步骤。
3. 有未命中项时，执行 `python3 scripts/reference_files.py upload <目录>`。把 `{ "files": [...], "references": [...] }` 通过标准输入传入，其中两个数组分别来自第 1、2 步。脚本只压缩新增或修改的文件，保留比例及透明度，最长边 1600 像素，以 500 KiB 为目标，最多 1 MiB。设备需有支持 WebP 的 Pillow 或 ImageMagick 7。测试环境使用不同地址时，将用户确认的 Lycobo 源站传给 `--base-url`。
4. 从脚本输出的 `files` 取得对应的 `assetId`，去重后作为 `referenceAssetIds` 传给 `generate_image` 或 `generate_image_set`。每个任务最多 5 个；同一套图共用一组参考图，产品不同就按各套需要分别传。参考图缺失、变化或上传失败时，暂停受影响的任务并报告原因。凭证到期或文件变化时重新计算与查重。新任务提交后保留这次的原参数和请求 UUID。

请求头内的长期 Key 仍由连接器管理。把短期上传凭证仅交给本地脚本的标准输入。对话、任务说明和日志中都省略凭证及本地文件路径。如果定时任务无法访问本地电脑，或连接器缺少 `prepare_reference_uploads`，说明需要在本地模式运行或刷新连接器。

## 提交回执

从工具的 `content` 文本项读取 JSON。收到任务 `id` 即代表 Lycobo 已受理。保存 `id`、`publicId` 和 `historyUrl`，简短回复「已提交 · 任务编号 WS8TZGMH5」，用回执中的实际短编号，并将编号链接到 `historyUrl`。多套时汇总已提交数量，每套列名称和编号，单独说明未获受理的原因。比例与要求不符时，注明 Lycobo 回执里的实际比例。

默认在全部提交处理完后结束本轮。只有用户明确要求自动下载时，才按下节为该任务启动本机下载。
