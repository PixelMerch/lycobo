# Lycobo 生图

## 连接 Lycobo

使用支持技能导入和 Streamable HTTP MCP 的 Agent。已开通的账号可从 Lycobo 头像菜单进入「应用连接」，在「技能与密钥」签发生图 Key 并下载技能。使用「配置连接」复制连接地址和请求头值，并在 Agent 中添加 HTTP 连接器。导入后通过连接器调用工具。工具有命名空间时使用注册后的完整工具名。

请求头名称为 `Authorization`，值为 `Bearer <生图 Key>`。把值只保存在连接器鉴权设置中。对话、提示词、任务描述和示例里都省略真实 Key。工具缺失、凭据无效或账号未开通时，说明对应问题，并引导用户检查「应用连接」。

## 提交生图任务

通过当前连接器的 `aspectRatio` 参数指定宽高比。字段缺失时，提示刷新 Lycobo 连接器的工具列表，暂停提交。

1. 保留用户指定的商品特征、文案语言和构图。优先使用用户指定的宽高比。只指定用途时选择合适的 `aspectRatio`，例如竖版商品海报 `4:5`、全屏竖图 `9:16`、横幅 `16:9`。用途也不明确时用 `1:1`。分辨率支持 `1.5K`、`2K`、`4K`，默认 `1.5K`。需要参考图时，先按下节取得素材 ID。
2. 生成一张独立图片时，调用 `generate_image`，传入 `prompt`、`resolution`、`aspectRatio` 和 `requestId`。`prompt` 为 1–5,000 字符。
3. 每套调用一次 `generate_image_set`，传入 `title`、`resolution`、`aspectRatio`、`requestId` 和 `images`。套名与每张图的标题都是 1–40 字符，套名至少包含一个字母或数字（含汉字），单图提示词为 5–4,000 字符。每套 1–20 张，套内共用同一比例。用户要求 10 套、每套 10 张时，直接提交 10 个独立任务，无需为总张数额外确认。单套超出 20 张时，说明上限并让用户决定如何拆分。
4. 每个新任务使用不同的 UUID 作为 `requestId`。提交前保留该 UUID 和原参数。网络超时、响应丢失等导致结果未知时，使用同一 UUID 和同一组参数有限重试。取得任务 `id` 后复用原任务。出现请求冲突时先核对已有回执与原参数。

下面是一套两张图的 `generate_image_set` 参数示例。每次实际提交都生成新的 UUID，同一任务重试除外。

```json
{
  "title": "亚麻床品",
  "resolution": "1.5K",
  "aspectRatio": "4:5",
  "requestId": "ec01a690-674a-4676-9f88-f1eecbdf7bd0",
  "images": [
    { "title": "商品主图", "prompt": "米色亚麻床品的正面图，窗边柔光，保留自然褶皱" },
    { "title": "纹理特写", "prompt": "相同米色亚麻床品的近景，突出织物纹理和边缘走线" }
  ]
}
```

## 使用本地参考图

在豆包的「本地电脑」中，让用户选一次文件夹并确认该文件夹可用于定时任务。保存所选目录、文件选择规则和各套图如何使用参考图。后续运行读取该目录里的匹配图片。仅用户授权的目录可读。Agent 需要能在本地运行技能内的脚本并访问连接器，云端环境无法读取这台电脑的文件。

1. 每次运行先确定各套要用的参考图。文件夹可以包含更多图片，每套挑选自己的参考图，最多 5 张。多套共用的图只准备一次。只对本轮选中的文件执行 `python3 scripts/reference_files.py fingerprint <目录> <文件1> <文件2> ...` 计算原文件 SHA-256，接受目录内的相对文件名或绝对路径。将每个路径作为独立参数传入，保留返回的 `files` 在本地。文件改名但内容相同会复用原素材。
2. 调用 `prepare_reference_uploads`，只发送 `{ "fingerprints": [...] }`。同一批内去重，每次最多 100 个。命中项返回 `sha256`、`assetId`；未命中项返回 `sha256`、`uploadUrl`、`uploadToken`。整批都命中时直接用对应 ID，跳过脚本的上传步骤。
3. 有未命中项时，执行 `python3 scripts/reference_files.py upload <目录>`。把 `{ "files": [...], "references": [...] }` 通过标准输入传入，其中两个数组分别来自第 1、2 步。脚本只压缩新增或修改的文件，保留比例及透明度，最长边 1600 像素，以 500 KiB 为目标，最多 1 MiB。设备需有支持 WebP 的 Pillow 或 ImageMagick 7。测试环境使用不同地址时，将用户确认的 Lycobo 源站传给 `--base-url`。
4. 从脚本输出的 `files` 取得对应的 `assetId`，去重后作为 `referenceAssetIds` 传给 `generate_image` 或 `generate_image_set`。每个任务最多 5 个；同一套图共用一组参考图，产品不同就按各套需要分别传。参考图缺失、变化或上传失败时，暂停受影响的任务并报告原因。凭证到期或文件变化时重新计算与查重。新任务提交后保留这次的原参数和请求 UUID。

请求头内的长期 Key 仍由连接器管理。把短期上传凭证仅交给本地脚本的标准输入。对话、任务说明和日志中都省略凭证及本地文件路径。如果定时任务无法访问本地电脑，或连接器缺少 `prepare_reference_uploads`，说明需要在本地模式运行或刷新连接器。

## 提交回执

从工具的 `content` 文本项读取 JSON。收到任务 `id` 即代表 Lycobo 已受理。保存 `id`、`publicId` 和 `historyUrl`，简短回复「已提交 · 任务编号 WS8TZGMH5」，用回执中的实际短编号，并将编号链接到 `historyUrl`。多套时汇总已提交数量，每套列名称和编号，单独说明未获受理的原因。比例与要求不符时，注明 Lycobo 回执里的实际比例。

全部提交处理完后结束本轮。跳过回执里的生成查询时点和间隔，省去等待、状态查询、预览、下载及图片展示。

## 处理失败

工具的 `isError: true` 表示调用未返回正常结果。读取 `code`、`message` 和可用的 `retryAfterSeconds`，按以下规则处理。

- 鉴权失败时检查连接器地址、`Authorization` 值和 Key 状态。修正后可继续原任务。
- 参数有误时指出字段与限制。内容审核拒绝时说明原因，等用户修改需求。积分不足时说明需要补充积分。收到这些明确拒绝后暂停对应提交。
- 限流时按服务端提示等待，重试仍使用对应任务的原 UUID。当前执行时间不足时，汇报已接收任务及尚未完成的步骤。
- 重试后仍无法确认受理时，标记为「提交未确认」并保留原 UUID 和参数，供后续继续同一次提交。

## 定时生图

所用 Agent 支持定时任务时，按用户给出的频率和时区设置，补问缺少的提示词、套数、每套张数或时间信息。创建计划时确定比例和分辨率，后续每次按计划提交。设置时说明 Lycobo 按张收取生图积分。每次触发创建新的任务 UUID，同一次触发内的重试复用原 UUID。每次运行只提交该次计划，按上面的回执格式汇报。
