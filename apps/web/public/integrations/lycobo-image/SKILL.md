# Lycobo 生图

## 连接 Lycobo

使用支持技能导入和 Streamable HTTP MCP 的 Agent。已开通的账号可从 Lycobo 头像菜单进入「应用连接」，在「技能与密钥」签发生图 Key 并下载技能。使用「配置连接」复制连接地址和请求头值，并在 Agent 中添加 HTTP 连接器。导入后通过连接器调用工具。工具有命名空间时使用注册后的完整工具名。

请求头名称为 `Authorization`，值为 `Bearer <生图 Key>`。把值只保存在连接器鉴权设置中。对话、提示词、任务描述和示例里都省略真实 Key。工具缺失、凭据无效或账号未开通时，说明对应问题，并引导用户检查「应用连接」。

## 提交生图任务

1. 保留用户指定的商品特征、文案语言和构图。优先使用用户指定的宽高比。只指定用途时选择合适的 `aspectRatio`，例如竖版商品海报 `4:5`、全屏竖图 `9:16`、横幅 `16:9`。用途也不明确时用 `1:1`。分辨率支持 `1.5K`、`2K`、`4K`，默认 `1.5K`。需上传参考图时，引导用户到 Lycobo 网页。
2. 生成一张独立图片时，调用 `generate_image`，传入 `prompt`、`resolution`、`aspectRatio` 和 `requestId`。`prompt` 为 1–5,000 字符。
3. 每套调用一次 `generate_image_set`，传入 `title`、`resolution`、`aspectRatio`、`requestId` 和 `images`。套名与每张图的标题都是 1–40 字符，套名至少包含一个字母或数字（含汉字），单图提示词为 5–4,000 字符。每套 1–20 张，套内共用同一比例。用户要求 10 套、每套 10 张时，直接提交 10 个独立任务，无需为总张数额外确认。单套超出 20 张时，说明上限并让用户决定如何拆分。
4. 每个新任务使用不同的 UUID 作为 `requestId`。提交前保留该 UUID 和原参数。网络超时、响应丢失等导致结果未知时，使用同一 UUID 和同一组参数有限重试。已经取得任务 `id` 后，用 `get_image` 查询该任务。出现请求冲突时先核对已有回执与原参数。
5. 保存回执里的 `id`、`publicId` 和 `historyUrl`。回复用户时显示实际 `publicId` 和提交时所用比例，例如「任务编号 `WS8TZGMH5` · `4:5`」。`id` 是内部任务 UUID，`replayed: true` 表示复用了原任务。多套提交时，每套对应自己的套名、短编号和状态。

下面是一套两张图的 `generate_image_set` 参数示例。每次实际提交都生成新的 UUID，同一任务重试除外。

```json
{
  "title": "亚麻床品",
  "resolution": "1.5K",
  "aspectRatio": "4:5",
  "requestId": "ec01a690-674a-4676-9f88-f1eecbdf7bd0",
  "images": [
    { "title": "商品主图", "prompt": "米色亚麻床品的正面图，窗边柔光，保留自然褶皱" },
    { "title": "纹理特写", "prompt": "相同米色亚麻床品的近景，突出织物纹理和边缘走线" }
  ]
}
```

## 查询与交付

用户要在对话里收图时，提交后接着调用 `get_image` 查询，可以在 `taskId` 里传入短编号 `publicId` 或任务 UUID `id`。已有任务直接查询。工具把 JSON 放在 `content` 的文本项里时，从该项读取状态、短编号和链接。

- `queued` 或 `running` 时，按 `retryAfterSeconds` 等待。一次执行中，同一任务最多查询三次。还在运行时，返回任务编号和当前状态，供用户稍后继续查询。
- `succeeded` 时，显示任务编号、已完成的图片及各张原图的下载入口。`partially_failed` 时，说明部分失败，继续交付实际返回的图片。
- `failed` 或 `needs_reconciliation` 时，报告失败或待核对。重新提交可能再次消耗积分，先由用户确认。

对话里展示图片时优先调用 `preview_image`，传入任务编号和 `imageIndex`（从 1 开始，默认第一张）。若客户端无法渲染返回的 MCP 图片，提供 `get_image` 的 `images[].previewUrl`，让用户点开缩略图。用户要求看多张时，可按 `imageIndex` 列出每张的预览链接。

把 `images[].url` 作为对话里可点击的「下载第 N 张原图」链接，直接下载文件。预览和下载地址均以 `expiresAt` 为到期时间，默认 15 分钟。过期后按原任务编号再查 `get_image` 以刷新链接。用户需要整套 ZIP 或网页记录时，提供 `historyUrl`。

## 处理失败

工具的 `isError: true` 表示调用未返回正常结果。读取 `code`、`message` 和可用的 `retryAfterSeconds`，按以下规则处理。

- 鉴权失败时检查连接器地址、`Authorization` 值和 Key 状态。修正后可继续原任务。
- 参数有误时指出字段与限制。内容审核拒绝时说明原因，等用户修改需求。积分不足时说明需要补充积分。收到这些明确拒绝后暂停对应提交。
- 限流时按服务端提示等待，重试仍使用对应任务的原 UUID。当前执行时间不足时，汇报已接收任务及尚未完成的步骤。
- 提交结果不确定时保留原 UUID，避免重复提交和扣费。查询失败时保留既有任务链接和任务 ID。

## 定时生图

所用 Agent 支持定时任务时，按用户给出的频率和时区设置，补问缺少的提示词、套数、每套张数或时间信息。创建计划时确定比例和分辨率，后续每次按计划提交。设置时说明 Lycobo 按张收取生图积分。每次触发创建新的任务 UUID，同一次触发内的重试复用原 UUID。每次运行只提交该次计划，并按正常流程返回各套任务链接。
