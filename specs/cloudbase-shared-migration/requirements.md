# CloudBase 个人版完整迁移需求

日期：2026-10-31。状态：用户已明确迁移范围与套餐约束；实现方案待确认，尚未上线。

## 已确认范围

- 使用已开通的 CloudBase 国内站上海 `lycobo` 环境，保持个人版和共享 PostgreSQL；不升级套餐或独享实例。
- 迁移主站前端、API、独立后台任务和私有图片服务，同时迁移现有 Supabase PostgreSQL 业务结构和数据。
- 保留企业账号、密码哈希、组织关系、钱包余额、账本、任务历史、素材归属、公开编号及迁移记录。保留原有 UI 和浏览器 API 契约。
- 图片文件和展示变体单独迁移，数据库素材记录不能作为文件迁移成功的证据。
- 保留源数据库、源图片和旧部署；切换成功不等于获准删除旧资源。
- 不自动发起付费生图、不发布 Git 标签、不推送代码。

## 验收条件

1. 当用户通过原有企业账号登录时，新环境应验证迁移后的密码哈希并正确恢复组织身份，不以 CloudBase 用户替代原业务账号。
2. 当提交生成、退款、重试或任务认领时，共享 PG 应在数据库事务内维护原有余额、账本、任务、outbox、执行令牌与事件一致性；重复请求或消息不得重复扣费或调用供应商。
3. 当供应商提交结果不确定或消费者重启时，新系统应保留不确定状态及核对路径，不自动重提可能已经付费的请求。
4. 当访问素材时，系统应校验身份和归属，返回短期签名；私有原图和供应商密钥不得通过公开表、存储桶或客户端配置暴露。
5. 当完成数据库复制时，应核对表结构、行数、主外键、身份序列、迁移记录以及钱包与任务关联；切换前应建立同一冻结窗口下的最终快照。
6. 当完成图片复制时，应逐对象验证字节数与校验和、记录失败项，并验证原图、预览、缩略图和下载。
7. 当切换到 CloudBase 时，应验证页面深链、登录刷新与退出、组织隔离、钱包、历史、上传和任务恢复。仅页面可访问不得视为完整部署成功。
8. 当共享 PG 或个人版能力不满足上述条件时，应记录实际阻塞和替代方案，不自动升级套餐或降低业务保障。
