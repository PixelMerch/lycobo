# CloudBase 共享 PG 迁移设计草案

状态：数据库/图片复制、隔离恢复及主站运行仓储已实现验证，三个服务包已构建，实际云函数部署被凭据核对拦截。执行进度见 [运行迁移记录](../../docs/cloudbase-migration.md)。需求见 [requirements.md](requirements.md)，数据库执行结果见 [复制记录](../../docs/cloudbase-migration.md)。这是共享数据库约束下的工程方案，不代表现有系统已经兼容 CloudBase。

## 访问边界

浏览器继续请求同源 `/api`，Hono API 继续解析企业身份、组织与工作区；不将现有用户改成 CloudBase Auth 用户，不让浏览器直接访问业务表。CloudBase 资源凭据只注入服务端，由独立、可撤销的运行凭据访问共享 PG 和私有存储，不复用本地工具登录凭据。

当前 `postgres` 驱动连接、事务回调、行锁和 LISTEN 不能直接换成 SDK 链式 CRUD。共享 PG 路径应使用经验证的 SDK/HTTP 数据面，按领域暴露固定参数的数据库函数；不得创建接收任意 SQL 的通用运行入口，不把管理面 ExecutePGSql 用作线上数据库驱动。

## 事务迁移

数据库函数分别承接登录限流/会话轮换、任务提交与扣费、编辑/裂变计划幂等提交、任务认领、供应商状态持久化、完成/失败与退款、显式重试、outbox 租约及事件写入。每项函数必须保留原实现的锁顺序、组织校验、执行令牌校验、唯一约束和错误分类。

跨请求的 SDK 调用不能拼成事务。原 Node 事务必须整体移动到数据库函数中，外部供应商请求仍留在独立消费者、在事务之外完成。现有 Cloudflare 实现先保留，新增 CloudBase 仓储适配通过现有接口进入服务层，避免直接替换全部数据库访问。

业务表撤销 `anon`/`authenticated` 的直接访问权限；业务函数撤销 PUBLIC 默认 EXECUTE。函数使用显式 schema 和受控 `search_path`，执行权限只授予受控服务端角色。若运行凭据无法限制到所需函数，应作为发布阻塞处理。

## 后台任务与事件

PostgreSQL 保持任务和投递意图的真相来源。消费者与 HTTP API 独立部署。首先验证个人版支持的持久触发/传输方式、超时、重试和服务端认证；在验证前不声称后台任务可运行。若选择直接消费 PostgreSQL outbox，必须验证租约续期、进程中断恢复、并发领取、失败退避和异步供应商轮询；不能以 HTTP handler 内后台 Promise 替代。

SSE 继续使用持久事件游标和组织隔离，可采用现有轮询恢复语义；共享 PG 不依赖常驻 LISTEN。访问路径必须实测长连接超时与断线恢复。

## 私有图片

先盘点现有对象存储及旧 R2 回退记录，再决定 CloudBase PG 私有存储的服务端适配。保留对象 key、归属与预览/原图用途隔离，复制时计算校验和。新环境读取验证完成前不改写源对象引用。展示变体生成需替代 Cloudflare Images；不得回退为将原始大图放入网格。

## 数据迁移及切换

1. 私有完整备份、隔离恢复验证，检查源业务对象与目标系统 schema 的冲突。
2. 在空目标上应用明确版本的结构迁移；不导入 Supabase `auth`、`storage` 系统 schema，不重放历史迁移后再次导入同一结构。
3. 使用共享 PG 支持的管理导入或受控数据面分批复制业务行，保留 UUID、密码哈希、加密密文、时间戳与精度；按依赖顺序处理外键和身份序列。
4. 验证所有数据库函数的并发、失败和幂等行为，再接入 API 与消费者；生成保持关闭。
5. 复制并校验图片，在候选域名完成只读、鉴权及上传验收。
6. 最终切换前暂停源站业务写入和消费者，确认没有在途/不确定付费提交，取得最终快照并核对。独立 admin 共享部分表，必须同步处理其写入边界，避免切换后双写分叉。
7. 同时切换主站 API、消费者、图片服务和相关 admin 连接；验收成功后恢复提交。需要付费生成验收时单独确定账号与消费限额。

## 回退

复制阶段保留源库和对象。切换前失败可继续使用源部署。切换后若新库已产生写入，禁止直接将流量切回旧库；先停写、核对新写入并设计回迁，防止余额、任务或会话丢失。任何删除或清理源资源另行授权。

## 验证

代码变更运行 `pnpm check`；数据库/消费者变更遵循 `docs/testing.md` 的隔离测试要求。新增共享 PG 集成验证使用明确的隔离 schema/环境，不在生产业务表创建测试账号或演示余额。候选部署执行聚焦浏览器检查，不默认运行全量 E2E。记录实际 URL、部署版本、数据校验结果与尚未验证的外部调用。
