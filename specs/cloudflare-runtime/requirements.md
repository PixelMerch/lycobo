# 纯 Cloudflare Workers 迁移：需求

更新：2026-11-06。用户已确认：dev 不再兼容 CloudBase，全部应用计算迁至 Workers，图片处理放 Queue，视频暂不接入。本次只完成代码、本地验证与本地提交；部署、推送、创建云资源及真实付费调用另行授权。

## 范围

- React/Vite 使用 Workers Static Assets；Hono API、签名私有媒体和 Queue/Cron 使用 Workers。
- 图片转换使用 Images binding；不引入 Containers，不在 Worker 中运行 Sharp/FFmpeg。
- 保留现有新加坡 PostgreSQL 与私有 R2；不迁移 PostgreSQL 到 D1，不再次复制或删除业务数据。
- 移除 CloudBase 运行适配、消费者唤醒与部署工作流；历史 SQL、备份证据和一次性源文件迁移工具保留。
- Node/Sharp/S3 仅用于隔离本地开发、既有集成测试；Worker 不挂载视频或 SSE。

## 验收条件

### R1：运行与权限

当请求 `/api/*` 时，Worker 必须执行 Hono API，不返回 SPA HTML。认证、可信来源、组织/用户归属、共享响应信封、请求 ID 与业务错误码必须保留。私有资源必须在验证签名、用途、来源、过期时间后访问 R2 或缓存；原始桶入口保持关闭。部署配置默认关闭任务执行，缺失配置不能回退 CloudBase 或伪造就绪。

### R2：上传与图片

当用户上传参考图时，HTTP 只暂存有大小限制的字节和服务端身份，返回待处理编号；Queue 负责真实格式/尺寸/动画校验、PNG 标准化和 WebP 变体。客户端必须等到素材在 PostgreSQL 登记成功后使用其 ID，不把 202 当作上传完成。跨用户/组织不能读取上传回执；重复消息与登记不得复制素材。浏览器本地压缩不替代消费者校验。

当处理供应商结果时，必须先保留已接收源文件，再转换并保存原图和展示变体。转换故障不能自动重新提交付费生成。Images 输入上限与旧输出契约的差异必须明确说明并验证，不能静默降分辨率。图片变体缺失通过 Queue 补齐，不能用占位图表示成功。

### R3：任务与账务

当 API 接受付费任务时，任务、扣费和 outbox 必须在 PostgreSQL 同一事务持久化，Queue 只携带编号。重复投递、延迟查询、失效旧执行和结果未决必须沿用现有幂等、租约、退款与对账规则。发送/确认间隙由 Cron 补投；不得把内存缓存当任务状态。

当首次接管时，只有固定接管时间后新建的执行项可以被领取、扫描超时和自动结算；复制的旧任务不得被自动执行或改账。Hyperdrive 禁用业务查询缓存，每次调用关闭数据库客户端。网络操作不进入数据库事务。

### R4：验证与交付

代码必须通过 pnpm check、git diff --check、隔离 PostgreSQL 集成，以及本地 workerd 的密码验证、Images/R2/Queue fixture。对上传轮询、权限、失效消息和失败恢复增加必要测试。不默认运行全量 E2E，不调用真实供应商；本地模拟通过不表示线上图片质量、性能和绑定已验收。
