# 海外后端统一部署到 Cloudflare：需求

更新：2026-11-06。状态：需求草案，尚未实施后端适配或部署。

## 目标与范围

海外前端与 `lycobo-api`、`lycobo-assets`、`lycobo-consumer` 的计算服务统一使用 Cloudflare，不新增独立 VPS。保留现有 Supabase 新加坡数据库、私有 R2 桶和已迁移文件；“统一 Cloudflare”在本阶段指计算与媒体存储，不迁移 PostgreSQL 到其他数据库产品。

默认建议 Workers 承接请求路由、Containers 承接需要完整 Node 运行环境的代码，以保留 sharp 与 FFmpeg 功能。若用户要求三个后端均为纯 Workers，需要在设计阶段确定图片转换、视频封面、数据库事件和任务执行的替代实现；不得通过删除现有能力来宣称迁移完成。

国内 CloudBase 内测继续使用原入口、数据库、私有存储与消费者，两端数据不自动同步。当前用户表示海外前端已部署；本阶段不把前端状态当作海外业务后端已可用的证据。

## 用户故事

- 作为使用者，我希望在海外站点完成登录、查看积分、上传素材、生成图片和视频，保持现有业务行为。
- 作为维护者，我希望计算服务在 Cloudflare 管理，配置按服务隔离，国内内测继续可用。
- 作为付费用户，我希望后台进程重启、重复回调或调度重试不会造成重复扣费或重复生成。

## 验收条件

### R1：平台与环境隔离

- 当启动海外服务时，系统必须使用海外 Supabase 与 R2 配置，并拒绝混用 CloudBase 的业务运行配置。
- 当变更海外入口或发布配置时，系统必须保留国内现有运行配置与数据，不启用双写。
- 当准备部署时，系统必须分别列出构建变量、Worker 运行变量、容器运行变量、Secret 与资源绑定，不把服务端密钥暴露到前端产物。

### R2：业务 API

- 当海外用户登录或查询业务数据时，API 必须保持现有认证、可信来源、资源归属和组织隔离规则。
- 当客户端访问 `/api/*` 时，入口必须转交海外 API，不将前端 SPA 的 HTML 回退当作 API 响应。
- 当返回 JSON 时，API 必须保持共享响应信封、业务码、HTTP 状态及请求 ID；二进制与流式接口保留原协议。
- 当上传图片时，服务端必须保留实际内容校验、大小与尺寸限制及既有图片处理，不仅信任扩展名或客户端 MIME。

### R3：私有媒体

- 当请求 `media.lycobo.com/images/*` 时，媒体服务必须验证签名、用途、过期时间和适用的来源规则后访问私有 R2。
- 当读取已迁移素材时，系统必须保留对象 key 与资源归属，支持预览图、缩略图、原图下载和视频 Range 播放。
- 当新素材需要展示变体或真实视频封面时，系统必须通过可验证的处理实现生成并缓存；不能使用样例或占位图替代成功。
- 当部署媒体服务时，R2 的直接公开桶入口必须保持关闭；签名链接不得进入日志。

### R4：任务与计费

- 当 API 受理付费任务时，任务、扣费和 outbox 意图必须在同一数据库事务持久化，实际生成在独立消费者执行。
- 当消费者被中断、休眠、重启或并发唤醒时，系统必须依赖持久状态、租约与幂等机制恢复，不依赖内存状态或永久运行的循环。
- 当供应商提交结果不明确时，系统不得自动再次提交付费生成；必须保留现有对账与用户确认重试规则。
- 当重复投递或重复回调到达时，系统不得重复扣费、入账或处理已失效的旧尝试。
- 当首次启用海外消费者时，必须先隔离快照复制的历史执行意图和 `needs_reconciliation` 任务；不得自动接管国内待处理任务。
- 当使用事件或延迟调度时，PostgreSQL 必须继续作为真实来源，触发器和消息仅承担唤醒，不替代账务持久化。

### R5：运行与恢复

- 当服务启动或关闭时，必须正确处理监听地址、端口、进程信号、数据库资源与未完成任务，保留各服务进程边界。
- 当健康检查通过时，只能说明被实际检查的依赖可用，不得以进程存活推断数据库或消费者就绪。
- 当配置模型凭据、签名密钥或 JWT 时，必须按海外环境隔离，并明确数据库中既有密文和复制会话的处置方式。
- 当发布候选版本时，必须有可复查的实例资源、并发、超时、唤醒、补查和回滚配置；费用以实际用量验证，不承诺固定低价。

### R6：验证与交付

- 当完成代码适配时，必须通过 `pnpm check`，并按数据库／队列变更范围执行隔离集成验证。
- 当验证生成与计费时，必须先使用隔离供应商 fixture；真实付费调用另需用户明确授权。
- 当准备上线时，必须验证登录、素材访问、路由刷新、上传、任务恢复、重复消息和回调等关键流程；完整本地 E2E 不默认执行。
- 当完成本阶段准备时，仅提交本地 dev，不推送、合并、创建版本、购买套餐或部署；后续操作分别获得用户授权。

## 当前需要在设计阶段解决的具体差异

| 代码与依赖 | 已确认现状                                    | 设计必须解决的事项                                |
| ---------- | --------------------------------------------- | ------------------------------------------------- |
| API 入口   | Hono Node HTTP server                         | Cloudflare 路由、容器或 Worker 入口与生命周期     |
| 图片处理   | sharp 原生依赖                                | 保留 Node 实现或验证替代方案等价性                |
| 视频封面   | ffmpeg-static 子进程和临时文件                | 真实解码能力与资源限制，不假定纯 Workers 原样支持 |
| 本地消费者 | 拒绝非本地数据库                              | 新增海外生产入口，不能绕过本地保护直接上线        |
| 国内消费者 | CloudBase Event 唤醒                          | 海外可靠唤醒、延迟补查和关闭恢复                  |
| 数据库事件 | 现有 Node LISTEN/NOTIFY 与 CloudBase 查询实现 | 与选定连接方式兼容，不能只替换 DATABASE_URL       |
| 运行配置   | 本地 `.env.cloudflare` 集中保存               | 显式按服务注入，不能假设控制台配置自动进入容器    |
